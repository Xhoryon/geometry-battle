# V1.1 — Algorithm Slot, Startup & JSON IPC Protocol

## 1. 目标

V1.1 对参赛算法采用完全标准化接口。

参赛者不能自行决定：

- 算法放在哪里；
- 主程序叫什么；
- 如何启动；
- 如何获得比赛数据；
- 如何返回函数；
- 输出文件叫什么；
- 使用 stdin/stdout 还是 socket；
- 是否建立自己的 API 服务。

赛事平台统一规定所有以上内容。

最终参赛者需要做的事情只有：

> 将自己的算法放入指定 Team 文件夹，并确保固定入口程序能够读取官方 JSON 输入并生成官方 JSON 输出。

---

# 2. 两个固定 Algorithm Slot

项目中永久保留：

```text
algorithms/
├── team-a/
└── team-b/
```

分别代表：

```text
algorithms/team-a/
→ Team A Algorithm Slot

algorithms/team-b/
→ Team B Algorithm Slot
```

正式比赛时：

```text
Team A 上传的算法
→ algorithms/team-a/

Team B 上传的算法
→ algorithms/team-b/
```

两个目录结构要求完全一致。

---

# 3. 标准算法目录

每支队伍至少必须包含：

```text
algorithms/team-a/
└── solver.py
```

以及：

```text
algorithms/team-b/
└── solver.py
```

允许参赛者添加自己的内部模块：

```text
team-a/
├── solver.py
├── optimizer.py
├── geometry.py
├── fitting.py
└── utils/
    └── ...
```

但：

```text
solver.py
```

必须存在，并且必须作为唯一正式入口。

---

# 4. 不允许自定义 Entrypoint

V1.1 不再允许：

```text
main.py
run.py
algorithm.py
my_solver.py
```

作为正式入口。

统一：

```text
solver.py
```

因此赛事方不需要读取：

```text
manifest.entry
```

来决定如何执行。

正式启动协议始终相同。

---

# 5. 固定 Runtime

V1.1 正式比赛冻结统一 Runtime。

例如当前比赛环境：

```text
Python 3.9.6
```

正式版本应同时冻结：

- Python version
- allowed packages
- NumPy version
- SciPy version
- SymPy version（若允许）
- CPU quota
- memory quota
- thread limit

双方环境必须完全相同。

---

# 6. 固定启动命令

Team A：

```bash
python3 solver.py \
  --team A \
  --public /input/public_state.json \
  --reveal /input/reveal_state.json \
  --output /output/result.json
```

Team B：

```bash
python3 solver.py \
  --team B \
  --public /input/public_state.json \
  --reveal /input/reveal_state.json \
  --output /output/result.json
```

双方唯一允许不同的是：

```text
--team A
```

与：

```text
--team B
```

其他：

- 文件名；
- 参数顺序；
- Runtime；
- 输入格式；
- 输出格式；

全部一致。

---

# 7. 比赛双方输入完全一致

两边获得：

```text
public_state.json
reveal_state.json
```

而且要求：

```text
SHA256(A/public_state.json)
=
SHA256(B/public_state.json)
```

同时：

```text
SHA256(A/reveal_state.json)
=
SHA256(B/reveal_state.json)
```

Team Identity 不写进 JSON。

因此：

```text
JSON_A == JSON_B
```

是可以直接验证的。

---

# 8. Round Sandbox 目录

每轮正式执行时，平台为 Team A / B 分别创建一次性 Sandbox。

逻辑结构统一：

```text
sandbox-A/
├── app/
├── input/
├── output/
└── work/
```

以及：

```text
sandbox-B/
├── app/
├── input/
├── output/
└── work/
```

---

# 9. `/app`

例如 A：

```text
/app/
├── solver.py
├── optimizer.py
└── ...
```

来源：

```text
algorithms/team-a/
```

B 则来自：

```text
algorithms/team-b/
```

正式运行版本必须来自已经：

```text
Preflight
↓
Hash
↓
Seal
```

的算法快照。

`/app`：

```text
READ ONLY
```

比赛期间不能修改。

---

# 10. `/input`

包含：

```text
/input/
├── public_state.json
└── reveal_state.json
```

权限：

```text
READ ONLY
```

算法不能修改。

---

# 11. `/output`

只用于正式结果：

```text
/output/
└── result.json
```

每 Round 开始时：

```text
/output/
```

必须为空。

---

# 12. `/work`

允许算法使用临时计算文件：

```text
/work/
```

但：

```text
Round End
↓
Destroy Sandbox
↓
Destroy /work
```

下一轮不会保留。

# 13. public_state.json

揭盲之前生成。

例如：

```json
{
  "schema_version": "1.1",
  "match_id": "MATCH-001",
  "round": 5,

  "map": {
    "xmin": -20,
    "xmax": 20,
    "ymin": -12,
    "ymax": 12
  },

  "points": [
    {
      "id": "A1",
      "team": "A",
      "x": -14,
      "y": 6,
      "alive": true
    },
    {
      "id": "A3",
      "team": "A",
      "x": -8,
      "y": -2,
      "alive": false
    },
    {
      "id": "B1",
      "team": "B",
      "x": 9,
      "y": 4,
      "alive": true
    }
  ]
}
```

---

# 14. Public State 必须包含死亡点

不要只发送 Alive Points。

所有原始比赛点继续存在，例如：

```json
{
  "id": "B3",
  "x": 14,
  "y": 2,
  "alive": false
}
```

这样算法能够完整理解历史地图结构。

但死亡点不能：

- 被选择为 Shooter；
- 再次被击杀。

---

# 15. Public State 禁止隐藏信息

其中绝对不能出现：

```text
obstacles
shooters
hidden_seed
generator_seed
future round
future obstacles
precomputed judge result
```

尤其：

```text
seed
```

如果能够用于推导障碍物，就绝不能传给算法。

---

# 16. reveal_state.json

双方人工选择 Shooter 后生成。

例如：

```json
{
  "schema_version": "1.1",
  "match_id": "MATCH-001",
  "round": 5,

  "public_state_sha256": "abc123...",

  "shooters": {
    "A": "A4",
    "B": "B2"
  },

  "obstacles": [
    {
      "id": "O1",
      "type": "rectangle",
      "xmin": -2,
      "xmax": 1,
      "ymin": -3,
      "ymax": 2
    },

    {
      "id": "O2",
      "type": "circle",
      "cx": 5,
      "cy": 3,
      "radius": 2
    }
  ]
}
```

---

# 17. Reveal State 是 Delta

第二份 JSON 不重新复制：

```text
points
alive
map bounds
```

它只增加：

```text
shooters
obstacles
public-state binding
```

所以：

```text
Round State
=
public_state
+
reveal_state
```

避免同一个数据出现两个版本。

---

# 18. START 前算法绝对不能运行

正式状态：

```text
public_state.json generated
↓
NO USER ALGORITHM

Shooter selection
↓
NO USER ALGORITHM

Reveal
↓
reveal_state.json generated
↓
NO USER ALGORITHM

WAITING FOR START
```

只有：

```text
START
```

以后：

```text
solver.py
```

才第一次执行。

---

# 19. “同时启动”的正式定义

物理计算机上无法保证两个 Python 指令在完全相同的纳秒执行。

因此正式定义为：

> Team A 与 Team B 由同一个 Judge GO 事件释放，并通过相同的 Runner 启动路径启动。

流程：

```text
Sandbox A READY
Sandbox B READY

public A/B hashes verified
reveal A/B hashes verified

        ↓

      BARRIER

        ↓

Judge presses START

        ↓

      GO EVENT

      ┌────┴────┐
      ↓         ↓
  RELEASE A   RELEASE B
      ↓         ↓
 solver.py   solver.py
```

这就是赛事意义上的：

```text
SIMULTANEOUS START
```

---

# 20. START 前允许启动什么

可以提前运行：

```text
Platform
Judge
Sandbox Manager
Trusted Runner Wrapper
```

但是：

```text
参赛者 solver.py
参赛者任何 Python module
参赛者任何 executable code
```

不得运行。

也就是说可以提前把跑道准备好：

```text
Runner A READY
Runner B READY
```

但运动员还不能开始跑。

---

# 21. Trusted Runner Barrier

最推荐的实现不是让：

```text
solver.py
```

提前启动然后等待文件。

因为：

```text
solver.py running before START
```

本身就可能成为 preprocessing。

应该：

```text
Trusted Runner A
Trusted Runner B
```

先准备。

它们属于赛事平台，不包含参赛代码。

START 后：

```text
Trusted Runner
↓
exec solver.py
```

---

# 22. Timing

继续保持 V1.0 / V1.1 已验证的公平计时语义。

Team A：

```text
releaseA timestamp
→
valid result arrival
```

Team B：

```text
releaseB timestamp
→
valid result arrival
```

即：

\[
T_A=t_{result,A}-t_{release,A}
\]

\[
T_B=t_{result,B}-t_{release,B}
\]

而不是假装操作系统能够提供完全相同的纳秒级起跑时间。

---

# 23. 两边 Release 必须来自同一 GO

虽然正式计时以各自 release 为起点，但：

```text
release A
release B
```

必须由一个共同：

```text
GO EVENT
```

触发。

平台同时记录：

```text
releaseA_ns
releaseB_ns
startSkew_ns
```

其中：

\[
startSkew=|release_A-release_B|
\]

用于审计。

---

# 24. 算法不能通过 stdout 返回比赛结果

V1.1 正式 IPC 统一使用：

```text
JSON FILE
```

因此：

```text
stdout
```

不作为算法结果通道。

算法必须生成：

```text
/output/result.json
```

---

# 25. result.json

正式格式建议冻结为：

```json
{
  "schema_version": "1.1",
  "dsl": {
    "type": "add",
    "args": [
      {
        "type": "mul",
        "args": [
          {
            "type": "number",
            "value": 0.3
          },
          {
            "type": "variable",
            "name": "x"
          }
        ]
      },
      {
        "type": "number",
        "value": 2
      }
    ]
  }
}
```

---

# 26. Result 只能包含算法负责的信息

算法只决定：

\[
y=f(x)
\]

所以正式输出只应该包含：

```text
schema_version
dsl
```

不要允许：

```text
hits
targets
kills
winner
blockedBy
computeTime
shooter
team
```

这些都是平台已经知道或 Judge 应该计算的内容。

---

# 27. Output Atomicity

算法不应该直接慢慢写：

```text
result.json
```

否则 Judge 可能刚好读取一个只写了一半的 JSON。

推荐 SDK 要求：

```text
result.tmp
↓
write complete JSON
↓
flush
↓
atomic rename
↓
result.json
```

Judge 只监听：

```text
result.json
```

出现。

---

# 28. Result Deadline

当前：

```text
computeTimeout = 2000ms
```

继续冻结。

如果：

```text
result.json
```

在 deadline 前形成完整合法文件：

```text
OUTPUT RECEIVED
```

否则：

```text
TIMEOUT
```

---

# 29. Invalid Result

以下情况：

```text
result.json missing
invalid JSON
wrong schema_version
missing dsl
invalid AST
not C²
convexity >100
NaN/Infinity
doesn't pass Shooter
```

统一进入：

```text
INVALID SHOT
```

每 Round：

```text
ONE OUTPUT ONLY
```

不能重新提交。

---

# 30. stdout / stderr

既然数据通信统一走 JSON 文件：

### stdout

不作为 IPC。

可以直接：

```text
captured / limited / ignored
```

### stderr

允许用于有限 Debug Log。

例如：

```python
print("optimization stage 3", file=sys.stderr)
```

但：

- 有大小限制；
- 不影响正式 Judge；
- 不作为比赛结果。

```text

```

# 36. 完整 Round Protocol

最终冻结成：

```text
ROUND N
        ↓
Generate public_state.json
        ↓
Human Shooter Selection
        ↓
A LOCK
B LOCK
        ↓
Generate reveal_state.json
        ↓
REVEAL
        ↓
Audience sees obstacles + shooters
        ↓
WAITING FOR JUDGE
        ↓
Judge presses START
        ↓
Prepare/verify two fresh sandboxes
        ↓
BARRIER
        ↓
GO
        ↓
┌────────────────┬────────────────┐
│                │                │
RELEASE A    RELEASE B
│                │
solver.py        solver.py
│                │
read JSON        read JSON
│                │
compute          compute
│                │
result.json      result.json
└────────┬───────┴───────┬────────┘
         ↓               ↓
        Judge receives results
                ↓
          First Solver
                ↓
          First Attack
                ↓
    Second Attack / Cancellation
                ↓
          ROUND RESULT
```

# 39. SDK 应该给参赛者一个最简单模板

例如：

```python
import argparse
import json
import os

parser = argparse.ArgumentParser()
parser.add_argument("--team", required=True)
parser.add_argument("--public", required=True)
parser.add_argument("--reveal", required=True)
parser.add_argument("--output", required=True)

args = parser.parse_args()

with open(args.public, "r", encoding="utf-8") as f:
    public_state = json.load(f)

with open(args.reveal, "r", encoding="utf-8") as f:
    reveal_state = json.load(f)

team = args.team

# -------------------------
# YOUR ALGORITHM HERE
# -------------------------

dsl = {
    "type": "number",
    "value": 0
}

result = {
    "schema_version": "1.1",
    "dsl": dsl
}

tmp = args.output + ".tmp"

with open(tmp, "w", encoding="utf-8") as f:
    json.dump(result, f)

os.replace(tmp, args.output)
```

选手真正要改的只有：

```text
YOUR ALGORITHM HERE
```

# 40. 参赛者要求可以因此变得非常清楚

参赛者必须保证：

1. 根目录存在 `solver.py`；
2. 使用指定 Python Runtime；
3. 接受固定四个 CLI 参数；
4. 从两个 JSON 文件读取比赛数据；
5. Team Identity 只读取 `--team`；
6. 不访问网络；
7. 不读取规定目录之外的数据；
8. 不保存跨 Round 状态；
9. 在 2000ms 内生成 `result.json`；
10. 输出必须符合官方 DSL；
11. 不通过 stdout/socket/API 返回正式结果；
12. 不自行计算或声明 Hit/Winner。

# 42. V1.1 最终边界

V1.1 的正式接口到这里可以冻结为：

```text
ALGORITHM SLOT
    team-a/
    team-b/

ENTRYPOINT
    solver.py

RUNTIME
    fixed Python environment

INPUT
    public_state.json
    reveal_state.json

IDENTITY
    --team A/B

OUTPUT
    result.json

START
    common GO event

TIMING
    each solver from its own release timestamp

PREPROCESSING
    forbidden

CROSS ROUND STATE
    forbidden
```

赛事平台和算法之间不需要任何其他通信机制。
