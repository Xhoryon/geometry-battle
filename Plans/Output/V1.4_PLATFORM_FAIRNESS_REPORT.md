sandbox are semantically bit-exact under x → −x, A ↔ B (Levels 1–6 green; 119/120 probe pairs mirror round-by-round,

**平台之外、但必须写进裁判运行手册的事实**：裁判机 idle sleep 会让当轮双方 TIMEOUT 并按零击杀计入 STALEMATE 计数（§5.2）。

## 3. 方法 / Methodology

### 3.1 镜像变换 M 的定义

`tests/mirror-helpers.ts`（两套测试与两个实验脚本共用同一个 M）：

```text
x' = −x（−0 归一化为 0），y 不变；Team A ↔ Team B；id 前缀 A ↔ B 重标（A3 ↔ B3）；
障碍物逐个镜像且**保持数组顺序**（traceTrajectory 在接触点相同 ±1e-12 时取下标最小者）；
Emitter 互换并镜像；地图 stateHash 用生产 computeMapHash 重算（必然与原图不同 —— 比较的是语义，不是字节）；
函数 f'(x) = f(−x)：每个 variable 叶子换成 neg(variable)。IEEE-754 取负精确，故 f'(−x) 与 f(x) 逐位相等。
```

M 是对合（M∘M = id），由 `selfCheck()` 在 Level 1 断言。

### 3.3 Symmetry Probe（审计 fixture）

`tests/fixtures/algos/symmetry-probe/`，包哈希 **`86f59fe2d6a6fcda654e3ddaeb773e0809cacb20e9f8a5056044bab7f25973ae`**（2 个文件，6198 B，`inspectPackage` 实核）。
一切几何在局部前进坐标 u 里算（A：u = x − xe；B：u = xe − x；forward = +u），输出 AST 唯一与队别有关的是 u 子表达式
（A `sub(x, xe)`，B `sub(xe, x)`）。确定性、无随机、无时间依赖；沙箱内实测 18–20 ms。
**它不是选手**，不得作为 Tournament Mode 内置选手暴露。镜像输入 → 逐位镜像输出是可证明的，因此 L6 与自战 campaign 里
两场之间的任何语义差异都只能来自平台（引擎 / 校验 / 输入协议 / 沙箱）。

### 3.5 统计方法（`experiments/v1.4-fairness/stats.ts`，零依赖）

```text
比例:        精确二项检验（双侧 = 2×较小单侧尾），Clopper–Pearson 95% CI；H0: P = 0.5
配对差:      d_i = A_i − B_i；配对 t（正态近似）、符号检验（精确二项）、Wilcoxon 符号秩（结修正 + 连续性修正）；
             效应量 Cohen's d_z = mean(d)/sd(d)
分布:        两样本 Kolmogorov–Smirnov（渐近 p），比较 generator(seed) 的 A 侧分布与 mirror(generator(seed)) 的 A 侧分布
多重比较:    地图指标 14 个 → Bonferroni α = 0.001/14 = 7.14e-5
预登记规则:  地图偏差 CONFIRMED ⇔ 某指标 p_W < α 且 |d_z| ≥ 0.05；p 过线但 |d_z| < 0.05 记 DETECTABLE_NEGLIGIBLE；
             槽位 / 先手偏差 CONFIRMED ⇔ 精确二项 p < 0.01 且 CI95 不含 0.5；样本不足以把 ±5pp 排除 → UNRESOLVED
```

### 3.6 地图分布（`experiments/v1.4-fairness/mapstats.ts`，纯 TS，不起沙箱）

9 个 (难度 × 点数) 单元各 3000 个 seed（`generateMapOrNull`，记录回退），逐张图算 A/B 配对指标：

```text
meanAbsX / meanY / meanAbsY            本队全部出生点的 mean|x|、mean y、mean|y|
minClearance / meanClearance           本队出生点到最近障碍物的 min / mean 间距（distanceToObstacle）
emitterClearance / emitterAbsX         自动选定 Emitter（本队第 1 点）到最近障碍物的间距、|x|
losCount                               从 Emitter 出发、对每个敌方战斗点（对方第 2..n 点）用真实 judgeShot 结算一条经过
                                       Emitter 与目标的直线，目标出现在 hits 里 ⇒ 直线可达；走生产的 penetration /
                                       firstContactX / 出界截断，不是自写射线几何
nearestEnemyDist / meanEnemyDist       Emitter 到敌方战斗点的最近 / 平均欧氏距离
zoneObstacleOverlapX / zoneObstacleArea 障碍物与本队区域 [−20,−4] / [4,20] 的 x 投影重叠长度、落在区域内的面积
obstacleArea / obstacleCentroidCount   x<0 vs x>0 的障碍物面积、质心符号计数（A 侧 = 左半场）
```

每张图另算 M(map) 的同一组指标：(1) 逐位恒等 `metrics(M(map)).A === metrics(map).B`（同时检验 mirrorMap 与指标函数本身 ——
含真实 judgeShot —— 的镜像对称性；面积公式左右各写一套互为镜像的表达式，否则 `total − left` 会在最后一位 ulp 上造假差异，
smoke run 里 180 张图有 99 处这种假差异，修正后为 0）；(2) KS 比较两组 A 侧分布。

### 4.4.0 先手顺序为什么不影响胜负（代码事实，先于数据）

`src/core/Match.ts`：

```text
:1016-1031  firstSolver 由 tA / tB 决定（|tA−tB| ≤ TIE_EPS_MS=0.05 → 'tie'），order 只决定 resolveOrderedShots 的执行顺序
:1038-1049  resolveOrderedShots({ order, simultaneous, points, emitters, ast, obstacles }) → attacksExecuted = order 里 shots 非 null 者
:1680-1710  for (const team of order) { enemies = alive.filter(p => p.team !== team); judgeShot(fn, emitters[team], team, enemies) ;
            非并列时 markDead(outcome.killed) }
:1074-1075  aKills 只数 startsWith('B') 的被杀点，bKills 只数 startsWith('A') 的
```

A 的一击只能移除 **B 队**的点，B 的一击只能移除 **A 队**的点；Emitter 不在 `points` 里、不会死，也没有任何「攻击取消」路径
（Locked Attack Right，Rule Revision 3 §3/§8）。于是先手方的击杀改变的是**后手方的目标集合的补集**，后手方看到的己方敌人集合
与回合开始时完全相同 —— 双方各自的 kills 与执行顺序无关，并列同时结算亦然。**firstSolver 不能造成胜负偏差**；它只是被记录
（RoundLog.firstSolver）与显示（观众板 lastRound.firstSolver、回放）的量。因此 §4.4 的先手统计回答的是「计时锚点是否对称」，不是「谁占便宜」。

## 5. 平台缺陷 / Platform bugs found & fixed

### 5.1 已确认并修复：Validator 采样网格锚点（f24ffa7）

`validateAttackFunction` 的四条采样循环（有限性、跳变窗口、斜率、凸性）原本都从 `domain[0]` 起步；A 的 `domain[0]` 是 Emitter，
B 的却是场地边 −20（`Rules.firingDomain`），同一个镜像函数在两边被采到两组不同的 x，阈值附近会翻转。

```text

            A：凸性变号 101 → CONVEXITY_LIMIT（非法）；镜像给 B：变号 100 → 合法
修复:       网格从本队 Emitter 出发沿进攻方向推进（min(sx + i·h, 20) ↔ max(−sx − i·h, −20)，精确镜像）；
            凸性二阶差分改写为 ((fp + fm) − 2·f0) 以在镜像网格上逐位相同
对 A 的影响: 采样点与修复前完全一致；6000 个贴阈值函数上结论 / 错误码 / 凸性计数 / max|f| / max|f'| 全同，
            仅信息性度量 maxAbsCurvature 在最后一位 ulp 上不同（2324/6000），它不参与判定

            8 族 2400 个随机函数里 0 个
```

### 5.2 不是平台 bug、但必须写进运行手册：宿主休眠会让双方同回合 TIMEOUT

probe campaign 第 23 场（seed 501111→501113，hard 6p，orig）第 3 回合 `RoundComputeStart` 14:38:48 → `RoundComputeEnd` 14:46:42，
474.3 s；双方错误码都是 TIMEOUT，`readySkewMs = 0`、`startSkew_ns = 0`（runDuel 的 READY 失败分支），result `TECHNICAL_INVALID`。
`pmset -g log`：14:37:59 `Entering Sleep state due to 'Idle Sleep'` → 14:38:02 DarkWake 45 s → 14:38:47 `Entering Sleep state due to
'Maintenance Sleep' … 475 secs` → 14:46:42 `Wake … pwrbtn / UserActivity`。**宿主睡着了**，两个 20 ms 的 probe 进程被冻结在 READY 之前。
该回合零击杀、计入僵持计数，orig 因此多打一轮（25 vs 镜像场 24），这一对被 pairCheck 如实标为 violation（见 §4.3.1，并附独立重跑）。
后续 campaign 以 `caffeinate -i -w <pid>` 阻止 idle sleep，未再出现。

**给裁判运行手册的事实**：正式比赛期间裁判机进入 idle sleep 会让当轮双方 TIMEOUT，且该轮按零击杀计入 STALEMATE 计数（Rule Rev 3 §15/§16）。
这不是引擎缺陷（引擎按规则处理了双 TIMEOUT），但是可操作的风险：赛前 `caffeinate -dims` 或关闭自动睡眠。

## 6. 局限 / Limitations

- **样本量的灵敏度**：槽位胜率的 CI 半宽约 ±11–14 pp（每个 solver 原局 43–68 场分胜负）；把 SLOT WIN BIAS 判为 DISPROVEN 的主要依据
  不是胜率点估计，而是 **167/167 对镜像配对胜者互换**这一确定性事实（对确定性 solver 这是逐字节可复核的）。
  若要单靠胜率把 ±5 pp 排除，需要约 1500 场分胜负的比赛。
- **负载**：campaign 期间前端 / e2e 代理并行工作，load 2.3–5.9；probe 的 93 ms 中位耗时与 18.7% 并列率都受此影响。
  负载对双方对称（a−b 中位 0.007 ms），但绝对耗时不代表安静环境。
- **宿主休眠**造成的 1 个 TIMEOUT 回合（§5.2）已通过独立复跑排除；后续 campaign 用 `caffeinate` 保护。
- **B-v1 的非确定性**（时间预算搜索）使其配对检查只能作参考（86/90）；它的原局 A 侧劣势（合并 p = 0.029）未能在本轮分辨为噪声还是策略交互。
- **地图分布**只检验了分布对称，不检验逐 seed 镜像不变（生成器结构上不可能：同一条 RNG 流先抽障碍物再放 A 队再放 B 队）；
  生成器种子回退率 27.2%（「指定的 seed 与实际地图对不上」），是操作体验问题，与对称无关。
- **未覆盖**：Web 服务端路径（`MatchSession`）下的公平性未单独测量 —— 它只是对 `MatchEngine` 的一次调用，判定同源；
  `timing-fairness` 套件（`runDuel` 释放次序）仍以 `aFasterRate ∈ (0.4, 0.6)` 守着，本轮未改其阈值。
- **A-v1 未用作证据**（Team-B 槽位枚举塌缩 bug 已知）。
