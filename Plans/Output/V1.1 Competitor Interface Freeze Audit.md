### BLOCKER

**B-1 `[A]` 运行时包清单与沙箱实际能力自相矛盾**

- *文档说*：README §5「正式比赛冻结统一 Runtime，双方环境逐项一致」，表中 `numpy | 2.0.2`、
  `scipy | 1.13.1`；《参赛算法开发要求》§3「允许使用哪些第三方 Python Package，
  以赛事最终发布的 **Runtime Manifest** 为准」——而该 Manifest 在仓库中**不存在**。
- *实现做*：沙箱 `scrubEnv` 设置 `PYTHONNOUSERSITE=1`，SBPL 又 `(deny file-read* (subpath "/Users"))`。
  本机 numpy/scipy 只存在于用户 site-packages
  （`/Users/jiayihuang/Library/Python/3.9/lib/python/site-packages`），因此沙箱内
  `import numpy` / `import scipy` **一律 `ModuleNotFoundError`**（沙箱内探针实测 BLOCKED）。
- *自证不一致的证据*：平台自身的 `RuntimeFrozen` 审计事件在**宿主**上探测，报告
  `mismatches: []` 且 `detected.packages = {numpy:"2.0.2", scipy:"1.13.1", sympy:null}`，
  即它**无法发现**"文档承诺、沙箱拒绝"这一差异。直接验证：
  `PYTHONNOUSERSITE=1 /usr/bin/python3 -c "import numpy"` → `ModuleNotFoundError`。
- *后果*：一个照着 README §5 写 `import numpy` 的独立 Agent，Preflight 会以一条
  **被截断的 traceback**（见 I2）失败，且失败原因看起来像它自己的 bug。
- *注*：这是**文档与观测口径**问题，不是接口问题——若官方机器把 numpy 装进系统
  site-packages，沙箱本可读取。必须二选一收敛口径（见"Required Changes"）。
