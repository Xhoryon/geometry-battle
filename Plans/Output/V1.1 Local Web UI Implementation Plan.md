# V1.1 Local Web UI — Implementation Plan

> **执行方式**：inline（`superpowers:executing-plans`）。用户指令为「写 spec 后直接实施，不再等待确认」。
> **本计划的写法说明**：本计划的执行者与设计者是同一会话、持有完整 spec 上下文，因此计划给出
> **精确文件清单、接口签名、任务边界与验证命令**，而不把每一行实现代码预先抄写一遍
> （那会写两遍、且第一遍必然与第二遍漂移）。**验证命令与期望输出一律照写，不得省略。**

**Goal**：把已冻结的 Engine / Judge / Replay 包装成 `npm run app` 一键启动的本地 Web 比赛应用，
不新增任何判定。

**Architecture**：`src/server/` 是唯一的 `MatchEngine` 持有者与白名单投影层；REST 发命令、WS 推
board；`web/` 是 React + Vite 的纯渲染客户端。

**Tech Stack**：TypeScript（服务端 CommonJS / ts-node）、Node 22 内置 `http`、`ws`、
React 19 + Vite 8 + Canvas 2D、Playwright（演练）。

## Global Constraints

- 冻结面：`src/core/`、`src/runner/`、`src/map/`、`src/submission/`、`competitor-kit/` **零改动**。
  `src/operator/judge.ts`、`src/ui/*`、`src/visualizer/*` **零改动**（终端 fallback 保真）。
- 规则数值零改动：Revision 3、`COMPUTE_TIMEOUT_MS=500`、`STALEMATE_NO_PROGRESS_LIMIT=20`、
  `HARD_ROUND_LIMIT=60`。
- 服务端**不得**出现任何命中 / 先手 / 击杀 / 胜负 / 僵持的计算。
- 观众板是**白名单拷贝**：没被拷贝的字段浏览器收不到。
- 轨迹**只发一次**（新轨迹产生时 + WS 连接建立时补推），**绝不**随 100ms ticker 重复广播。
- 浏览器**只做 reveal 比例揭示**，从不求值函数。
- 绑定 `127.0.0.1`；REST/WS 做 Host + Origin 校验；replay 的 matchId 走服务端映射。
- 测试**必须**显式传临时 `--slots` 与 `--artifacts`（曾把参考算法写进受跟踪的 `algorithms/`）。
- **不创建** `v1.1.0-competition` tag。

### Task 2：线上协议与投影（纯函数，TDD）
**Files**：Create `src/server/protocol.ts`、`src/server/boards.ts`、`tests/web-projection.ts`

**Interfaces（Produces）**：
```ts
// protocol.ts —— 零 node import
export const WS_TOPICS = ['judge', 'spectator'] as const;
export type Topic = (typeof WS_TOPICS)[number];
export interface ComputeCell { state: 'idle' | 'running' | 'done' | 'error'; timeMs: number | null; errorCode: string | null }
export interface SpectatorBoard { /* 见 spec §5.1 */ }
export interface JudgeBoard extends SpectatorBoard { slots; settings; runtime; audit; artifactDir; matchLogSummary }
export interface TrajectoryPayload { id: string; round: number; A: Point[]; B: Point[]; killed: string[] }
export type ServerMessage =
  | { type: 'hello'; topic: Topic; port: number }
  | { type: 'board'; topic: Topic; seq: number; board: SpectatorBoard | JudgeBoard }
  | { type: 'trajectory'; topic: Topic; trajectory: TrajectoryPayload }
  | { type: 'pong' };
export type ClientMessage = { type: 'ping' };
```

`protocol.ts` 需要 `Point` 与 `Obstacle` 的形状 —— **不得** import `src/core`（会把 node 依赖带进浏览器
bundle），改为在 protocol.ts 里声明结构等价的最小接口 `WirePoint { x: number; y: number }` /
`WireObstacle`（判别联合，与 `Obstacle` 结构兼容）。boards.ts 负责把真实 `Obstacle` 赋值进去，
由 TS 结构类型保证兼容。

- 步骤：先写 `tests/web-projection.ts` 的失败断言（白名单 / 投影 / 降采样 / 摘要），跑 → FAIL；
  再实现 `protocol.ts` + `boards.ts` → PASS。
- 白名单断言写法（spec §7.1）：把观众板 `JSON.stringify` 后扫描**禁用键名**
  （`hash` `sourceDir` `artifactDir` `isolation` `audit` `seed` `stack` `manifest`）与**绝对路径前缀**
  （`/Users/` `/var/folders/` `/private/` 以及 `PLATFORM_ROOT`）。**不写** `!includes('{')`。
- 摘要：`boardDigest(board)` 返回 phase/round/alive/各点存活位拼成的字符串，用于 ticker 去重。
- 验证：`npx ts-node tests/web-projection.ts` 全绿。

### Task 3：会话核心（命令串行化 + 轨迹缓存）
**Files**：Create `src/server/session.ts`

**Interfaces（Produces）**：
```ts
export interface CommandResult { ok: boolean; errors: string[]; detail?: Record<string, unknown> }
export class MatchSession {
  constructor(opts: { slotRoot: string; artifactRoot: string; sandboxRoot?: string; seed?: number; pointCount?: number; difficulty?: 'easy'|'medium'|'hard' });
  getBoard(topic: Topic): SpectatorBoard | JudgeBoard;
  getTrajectory(id: string): TrajectoryPayload | null;
  /** 订阅：board 摘要变化、新轨迹、命令完成 —— 由 ws 层挂载 */
  onChange(listener: (ev: SessionEvent) => void): () => void;
  newMatch(o: { seed?: number; pointCount?: number; difficulty?: 'easy'|'medium'|'hard' }): Promise<CommandResult>;
  install(team: 'A'|'B', sourceDir: string): Promise<CommandResult>;
  useSlot(team: 'A'|'B'): CommandResult;
  preflight(): Promise<CommandResult>;
  startMatch(): CommandResult;
  reveal(): Promise<CommandResult>;
  startRound(): CommandResult;
  compute(): Promise<CommandResult>;
  runToEnd(): Promise<CommandResult>;
}
export type SessionEvent =
  | { kind: 'board'; topic: Topic }
  | { kind: 'trajectory'; topic: Topic; trajectory: TrajectoryPayload };
```

- 串行化：`private chain: Promise<unknown>`；`private busy = false`。命令入口统一
  `if (this.busy) return { ok:false, errors:['上一条命令尚未完成'] }`。
- `reveal()` = `engine.beginRound()` + `engine.revealRound()`；`startRound()` = `engine.judgeStartRound()`；
  `compute()` = `await engine.computeRound()`，随后从 `engine.getReplay().frames` 取**最后一帧**，
  `downsampleTrajectory()` 后缓存为 `TrajectoryPayload`（id = `${matchId}:${round}`），并 `persistArtifacts`。
- `runToEnd()`：`while (engine.endReason() === 'NONE') { reveal; startRound; compute }`。
- ticker：`setInterval(100ms)` 读 `engine.getSnapshot()` → `boardDigest()` 变化才 emit `{kind:'board'}`。
  **不在 ticker 里碰轨迹。**
- `newMatch()`：保留旧 engine 的产物已落盘，然后按新参数构造 `new MatchEngine(...)`；`install/useSlot`
  **不**重复实现门禁 —— 直接把 `engine.upload()` / `engine.installAlgorithm()` 的结论透出。
- 验证：由 Task 4 的 `tests/web-server.ts` 覆盖。

### Task 4：安全、回放与 HTTP/WS 装配
**Files**：Create `src/server/security.ts`、`src/server/replays.ts`、`src/server/http.ts`、`src/server/ws.ts`、
`src/server/open.ts`、`src/server/main.ts`、`tests/web-server.ts`；Modify `tests/run-all.ts`、`package.json`

**Interfaces（Produces）**：
```ts
// security.ts
export function checkRequest(req: IncomingMessage, port: number): { ok: true } | { ok: false; status: number; message: string };
// replays.ts
export function listReplays(artifactRoot: string): { matchId: string; winner: string; endReason: string; rounds: number; endedAt: string }[];
export function loadReplay(artifactRoot: string, matchId: string): { ok: true; replay: unknown; match: unknown } | { ok: false; status: number; message: string };
// main.ts
export async function startServer(opts: { port: number; slotRoot: string; artifactRoot: string; open: boolean; dev: boolean; seed?: number; pointCount?: number; difficulty?: 'easy'|'medium'|'hard' }): Promise<{ port: number; close(): Promise<void> }>;
```

- `replays.loadReplay`：先 `^[A-Za-z0-9._-]{1,128}$` 且拒绝 `.`/`..`/含分隔符；再枚举
  `fs.readdirSync(<root>/matches)` 得到**服务端自有 id 集合**，参数必须命中；最后 `path.resolve`
  后断言仍在 `matches/` 下。未命中 → `{ ok:false, status:404 }`。**绝不拼接用户输入进路径。**
- `security.checkRequest`：Host ∈ {`127.0.0.1:<port>`, `localhost:<port>`}；POST 的 Origin 必须缺席或同源；
  POST 的 Content-Type 必须是 `application/json`。违反 → 403。
- WS upgrade 走同一套 Host/Origin 校验（`verifyClient` 或 `server.on('upgrade')` 手动校验后 `handleUpgrade`）。
- 静态资源：从 `web/dist` 提供；未知路径且非 `/api` 前缀 → 回 `index.html`（SPA fallback）。
  **必须**防御路径穿越（resolve 后仍须在 `web/dist` 内）。
- `tests/web-server.ts`（新增套件，注册进 `run-all.ts`）：
  - 起 `startServer({ port: 0, slots: tmp, artifacts: tmp, open: false })`
  - WS 连 `ws://127.0.0.1:<port>/ws?topic=spectator`，收集消息
  - 跑完整链路：`new-match` → `install A`（solver-fast）→ `install B`（solver-hybrid）→ `preflight`
    → `start` → 循环 `reveal/start-round/compute` 或直接 `run-to-end` → 断言 `MATCH_END`
    → `GET /api/replays` 含该场 → `GET /api/replays/:id` 成功
  - 断言：观众 topic 收到的 board 序列化后**不含**禁用键与绝对路径；`trajectory` 消息**恰好一次**
    （同一 id 不重复）；`run-to-end` 期间 board 至少出现 `COMPUTING`
  - 安全断言：伪造 `Host: evil.com` → 403；伪造跨源 `Origin` → 403；`/api/replays/..%2F..%2Fetc` → 404
  - **全部临时目录**（`tmpDir()`），显式传 `--slots`/`--artifacts` 等价物（这里是参数而非 CLI flag）
- 验证：`npx ts-node tests/web-server.ts` 全绿。

  **不重复实现门禁**（不许写 `phase === 'READY' && canStart` 这类影子规则）。
- `SpectatorPage`：无任何命令按钮、无路由外的诊断。
- 视觉由 `frontend-design` 技能定稿。

## 风险与对策

| 风险 | 对策 |

| 整目录导入把 React 依赖带进服务端 typecheck | `web/` 有独立 tsconfig，根 `include` 仍是 `src/**/*` |
