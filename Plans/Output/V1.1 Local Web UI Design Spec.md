# V1.1 Local Web UI — Design Spec

- **状态**：已批准（人输入任务书 [`../Input/Geometry Battle V1.1 Local Web UI.md`](../Input/Geometry%20Battle%20V1.1%20Local%20Web%20UI.md)）
- **基线**：RC `42e5417`（分支 `feature/v1.1-ui-protocol`）
- **日期**：2026-09-11
- **性质**：**包装层**。本设计不新增任何判定；所有权威状态来自现有 `MatchEngine`。

---

## 1. 目标与核心约束

把已经稳定的 Engine / Judge / Replay 包装成真正可用、**不需要 Terminal 或开发者介入**的本地比赛应用。

硬约束（来自任务书，逐条在本设计中落实）：

| 约束 | 落实方式 |
|---|---|
| Web UI 不得重新实现 timing / first solver / hit detection / obstacle / kills / winner / stalemate | 服务端只调用 `MatchEngine` 的既有方法，浏览器只渲染服务端投影 |
| 轨迹动画必须消费 Engine 已判定、已截断的 trajectory | 轨迹点由服务端下发 `ReplayFrame.trajectoryA/B` 的降采样副本；浏览器**只做 reveal 比例揭示**，从不求值函数 |
| 尽量不修改 `src/core/` `src/runner/` `src/map/` `src/submission/` `competitor-kit/` | 冻结面守卫：`git diff --name-only <base>..HEAD -- src/core/ src/runner/ src/map/ src/submission/ competitor-kit/` 必须为空 |
| 保留 `npm run judge` 作为 Terminal fallback | `src/operator/judge.ts` 与 `src/ui/*` **一行未改** |
| 不自行创建 `v1.1.0-competition` tag | 只提交，tag 留给最终审计方 |

规则数值一律不触碰：Revision 3 规则、`COMPUTE_TIMEOUT_MS = 500`、`STALEMATE_NO_PROGRESS_LIMIT = 20`、`HARD_ROUND_LIMIT = 60`。

## 2. 架构：视图投影服务端

```
web/  (React 19 + Vite，浏览器)
  /judge   /spectator   /replay/:matchId
  只做三件事：渲染 board、发命令、订阅推送
        │   REST = 用户操作        WS = 实时 board
src/server/   (ts-node，CommonJS，只读消费 src/core)
  protocol.ts   线上类型与消息名（纯类型 + 常量，零 node import，前后端共用）
  boards.ts     白名单投影 judgeBoard() / spectatorBoard()
  session.ts    MatchSession —— 唯一持有 MatchEngine；命令串行化
  replays.ts    已落盘回放的索引与加载（严格 matchId 校验 + 服务端路径映射）
  security.ts   Host / Origin 校验
  http.ts       路由 + 静态资源 + SPA fallback
  ws.ts         board 广播（topic = judge | spectator）
  open.ts       自动打开浏览器
  main.ts       启动、绑定 127.0.0.1、选端口
```

### 2.1 为什么是「视图投影」而不是「薄代理」

被否决的方案：`GET /api/snapshot` 直接把原始 `MatchSnapshot` 交给浏览器，由各页面自行挑选字段。

它的问题不是代码量，而是**保证的性质**：「观众看不见 hash / 路径 / 诊断」会退化成前端黑名单——只要有人往 `MatchSnapshot` 里加一个字段，观众屏就静默泄漏。本项目已经因为「UI 再猜一套规则」吃过两次亏（Revision 3 的 Emitter 单一来源、裁判台用 `phase === 'READY'` 猜门禁）。

本设计把这条保证变成**结构性事实**：观众板是**逐字段白名单拷贝**出来的，没拷贝到的字段浏览器**根本收不到**。

### 2.2 服务端不新增判定

每个命令 = 一次 `MatchEngine` 方法调用；每个 board 字段 = 一次引擎查询的拷贝。`src/server/` 内**不得出现**任何关于命中、先手、击杀、胜负、僵持的计算。

## 3. 线上协议

### 3.1 REST

所有 POST 返回 `{ ok: boolean, errors: string[], detail?: Record<string, unknown> }`。**预期内的失败不抛异常**（HTTP 200 + `ok:false`），让 UI 拿得到人话错误。

```
GET  /api/health                              → { ok, version, matchId | null }

# 比赛设置 / 生命周期
POST /api/judge/new-match   { seed?, pointCount?, difficulty? }  → 构造新 MatchEngine（Match Setup）
POST /api/judge/reset       { seed?, pointCount?, difficulty? }  → 等价于 new-match（保留语义别名）
POST /api/judge/install     { team, sourceDir }                  → Advanced：安装并密封进槽位
POST /api/judge/use-slot    { team }                             → 正式主流程：直接用槽位现成算法
POST /api/judge/preflight   {}                                   → 校验双方
POST /api/judge/start       {}                                   → 开始比赛（进入第一轮）
POST /api/judge/reveal      {}                                   → 揭晓本轮（REVEAL）
POST /api/judge/start-round {}                                   → START（此刻之前参赛代码一行都没跑）
POST /api/judge/compute     {}                                   → 结算本轮
POST /api/judge/run-to-end  {}                                   → 连续跑完余下回合直到终止

# 只读
GET  /api/judge/state                            → 裁判板（含槽位、包哈希、runtime、审计）
GET  /api/replays                                → 历史场次索引
GET  /api/replays/:matchId                       → 单场回放（轨迹已降采样）
GET  /api/trajectory/:id                         → 轨迹恢复路径（见 §4.2）
```

命令串行化：`MatchEngine` 不可重入。`MatchSession` 用 promise 链串行执行；命令进行中再发命令返回
`{ ok:false, errors:['上一条命令尚未完成'] }` —— **不排队、不静默吞掉**。

### 3.2 WebSocket

```
ws://127.0.0.1:<port>/ws?topic=judge|spectator

server → client:
  { type: 'board',       topic, seq, board }            # 小消息，摘要变化时才推
  { type: 'trajectory',  topic, id, round, A, B, killed }  # 新轨迹，每个 id 只推一次
  { type: 'hello',       topic, port }                  # 连接建立
client → server:
  { type: 'ping' }  →  { type: 'pong' }                 # 保活
```

**Compute status 的来源**：ticker 每 100ms 读一次 `engine.getSnapshot()` 的**摘要**（phase / round / alive / 各点存活位），只有摘要变化才推 board。这是纯读操作，不介入任何判定 —— 浏览器因此在长耗时的 `computeRound()` 期间仍能看到 `COMPUTING`。

### 3.3 轨迹的发送策略（不得随 ticker 重复广播）

轨迹是 board 里最大的载荷，**绝不随 100ms ticker 反复发送**。

- `board` 只携带一个**句柄**：`trajectoryHandle: { id, round } | null`
- 新轨迹在**本轮结算完成时推送一次**（`type:'trajectory'`）
- WS **连接建立时**，若当前存在轨迹，服务端补推该轨迹一次（重连恢复）
- 客户端按 `id` 缓存；若某条 board 引用了自己没有的 `id`（推送丢失的竞态），走
  `GET /api/trajectory/:id` 恢复

**浏览器只做本地 reveal 动画**：拿到 `A` / `B` 两组点后，用 `requestAnimationFrame` 按 elapsed
时间推进揭示比例。**从不重新求值函数** —— 重新求值会画出一条穿过障碍物的曲线（终端
`TrajectoryAnimator` 的注释已经记录过这条教训）。

轨迹为引擎判定后的**降采样副本**（复用 `downsampleTrajectory()`，最大 240 点）。

## 4. 安全（localhost 应用的边界）

服务端绑定 `127.0.0.1` 不足以阻止**跨站请求伪造与 DNS rebinding**：恶意网页可以令浏览器向
`http://127.0.0.1:<port>/api/judge/compute` 发请求。因此：

1. **Host 校验**：`Host` 头必须是 `127.0.0.1:<port>` 或 `localhost:<port>`，否则 403。
   （挡 DNS rebinding —— 攻击者域名解析到 127.0.0.1 时 Host 是攻击者域名。）
2. **Origin 校验**：状态变更请求（所有 POST）与 WS upgrade，`Origin` 必须
   **缺席**（非浏览器客户端，如测试脚本 / curl）或与 `Host` 同源，否则 403。
3. **Content-Type 强制**：POST 必须是 `application/json`，令跨站表单无法直接提交。
4. **不做 CORS**：不出 `Access-Control-Allow-Origin`，跨源预检直接失败。
5. **Replay 的 matchId 严格校验 + 服务端路径映射**：
   - 先按 `^[A-Za-z0-9._-]{1,128}$` 校验，且拒绝 `.` / `..` / 含 `/` 或 `\`；
   - 再**枚举** `<artifactRoot>/matches/*` 得到服务端自有的 id 集合，参数必须命中该集合；
   - 最后 `path.resolve` 后断言结果仍在 `matches/` 目录内。
   **绝不把用户输入拼接进文件路径。** 未命中返回 404。

## 5. board 投影

### 5.1 观众板（白名单）

```ts
interface SpectatorBoard {
  matchId: string;
  round: number;
  phase: MatchPhase;
  arena: {
    field: { xMin, xMax, yMin, yMax };
    obstacles: Obstacle[];
    emitters: { A: { id, position }, B: { id, position } } | null;
    points: { id, team, position, alive }[];
  };
  alive: { A: number; B: number };
  trajectoryHandle: { id: string; round: number } | null;
  computes: { A: ComputeCell; B: ComputeCell };   // { state, timeMs, errorCode }
  lastRound: { round, firstSolver, killed, aliveAfter } | null;
  verdict: { winner, endReason } | null;          // 仅 MATCH_END 非 null
}
```

**不含**：包哈希、包名、槽位目录、seed、audit、isolation、错误堆栈、任何文件路径。

### 5.2 裁判板

在观众板全部字段之上**追加**：槽位就绪（`status` / `hash` / `preflight`）、比赛设置（seed / points / difficulty）、
runtime frozen 比对、审计摘要（事件类型计数 + 事件列表）、产物目录。裁判可见诊断是**刻意**的 —— 它就是裁判台存在的理由。

### 5.3 白名单的回归保证

`tests/web-projection.ts` 对观众板做**序列化后**的禁用键 / 禁用子串扫描（见 §7），
并且这条断言是**结构性**的：观众板由显式字段构造，新增字段不会自动进入。

## 6. 页面

### 6.1 `/judge` 裁判台

```
┌───────────────────────────────────────────────────────────────┐
│ MATCH a1b2c3   ROUND 07   PHASE: COUNTDOWN   seed 123456  ●LIVE│
├────────────────────┬──────────────────────────────────────────┤
│ 算法槽位            │                                          │
│  Team A ● READY     │        ARENA（Canvas 2D）                 │
│  Team B ● READY     │   Ⓐ 障碍物 / 战斗点 / 固定 Emitter / 轨迹  │
│  [使用槽位算法]     │                                          │
│  ▸ Advanced         ├──────────────────────────────────────────┤
│    [替换 A][替换 B] │ COMPUTE   A ●●●● 0.284s │ B ○○○ 计算中…  │
│  [校验] [开始比赛]  ├──────────────────────────────────────────┤
│                     │ 动作 [揭晓][START][结算][跑完余下回合]     │
│ 本轮 R7             │      [回放][审计][重置/下一场]            │
│  first solver  A    │                                          │
│  attacked [A,B]     │                                          │
│  killed [B2,B5]     │                                          │
└────────────────────┴──────────────────────────────────────────┘
```

- **正式主流程是「使用槽位算法」**（零输入：算法已由选手投放到 `algorithms/team-a|team-b`）。
- **目录路径安装收在 `Advanced / Replace Algorithm` 折叠区**，是备用手段，不进主流程。
- 不做浏览器目录上传（`webkitdirectory` 只给 `File` 对象，需额外的 multipart 落盘层，收益不抵复杂度）。
- **Match Setup**：settings 面板（seed / 点数 / 难度）在 `new-match` 时生效；`点 数/难度` 与终端一致（默认 8 / medium）。

### 6.2 `/spectator` 只读大屏

满屏 Arena + 顶部一行（ROUND / A 存活 / B 存活 / FIRST）+ 底部计算状态。
**没有**哈希、路径、JSON、审计、控制台、动作按钮。此页面**不接受任何命令**（服务端也不为它提供）。

### 6.3 `/replay/:matchId`

同款 Arena + 回合滑条 + 播放/暂停 + 逐轮索引 + 结果横幅。
数据来自落盘 `replay.json` 与 `match.json`，回放期间**不运行任何算法**。

### 6.4 视觉方向

深色高对比、A/B 两队固定配色、计时用等宽数字、无边框噪音。实现阶段由 `frontend-design` 技能定稿。

## 7. 验证策略（Fast Verification Mode）

UI/API 改动只跑定向集；未修改 Timing / Sandbox / DSL，不重复重型 suites。

| 层 | 套件 | 内容 |
|---|---|---|
| 纯函数 | `tests/web-projection.ts` | 观众板白名单（**禁用键**与**绝对路径**扫描，不断言 `{`）、投影数学、降采样、board 摘要 |
| API 端到端 | `tests/web-server.ts` | 真 HTTP + 真 WS 起服务，跑完整链路：装算法 → 校验 → 开赛 → 多轮 → 终局 → 回放 → 重置 → 第二场；断言 WS 持续推进、观众 topic 不泄漏、Host/Origin 被拒、replay matchId 越权被拒 |
| 浏览器演练 | `web/e2e/tournament.spec.ts`（Playwright） | 真浏览器完整演练：启动 app → 载入两队 → Preflight → Match → 多 Round → 终局 → Replay → Reset → 第二场；并断言大屏页面文本不含诊断字样 |

参考算法：`playtest/competitors/solver-fast` vs `solver-hybrid`（`--points 6 --difficulty easy`），
与 `operator-e2e` 同一套参数。

**冻结面守卫**：改完后 `git diff --name-only <base>..HEAD -- src/core/ src/runner/ src/map/ src/submission/ competitor-kit/` 必须为空。
**最终**统一跑一次完整 `npm test` 作为 product regression。

### 7.1 明确不做的断言

- 不写「观众板不含 `{`」：序列化后的 JSON 本身就含花括号，该断言恒假或恒真，是假测试。
  改为扫描**禁用键名**（`hash` / `sourceDir` / `artifactDir` / `isolation` / `audit` / `seed` / `stack`）
  与**绝对路径前缀**（`/Users/`、`/var/folders/`、`/tmp/`、仓库根）。
- 不断言「平台完全确定」：计时不可重放（见项目记忆），只断言可重放的部分（胜负、击杀列表、哈希）。

## 8. 启动方式

```
npm run app      → vite build → 起服务 → 绑定 127.0.0.1:17800（占用则自动换端口）
                 → 打印 URL 并自动打开浏览器到 /judge
npm run app:dev  → 起服务 + 派生 vite dev server（HMR），/api 走代理
npm run judge    → 原样保留（终端 fallback，一字未改）
```

服务端默认槽位根 `<PLATFORM_ROOT>/algorithms`、产物根 `<cwd>/artifacts`，与终端裁判台一致；
`--slots` / `--artifacts` / `--port` / `--no-open` 可覆盖（**测试必须显式传临时目录**）。
