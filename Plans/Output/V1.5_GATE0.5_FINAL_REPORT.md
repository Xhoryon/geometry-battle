## Completed Fixes

### F1: Coordinate Denormalization (CLOSED)

**Problem**: Mixed normalized/denormalized coordinates in traceTrajectory.

**Root Cause**:
- Field coordinates: always normalized (-400, +400)
- generateMap: correctly produces normalized coordinates
- traceTrajectory: incorrectly used LEGACY constants

**Fix**:
- `traceTrajectory()`: Use normalized field bounds
- Removed legacy EMITTERS constants usage
- All coordinates now flow through single norm channel

**Evidence**: All 6 test cases pass
- Boundary probe at x=±400 correctly recognized
- No false OOB rejections
- Direction A/B symmetry preserved

---

### F2: Trajectory Boundary Drift (CLOSED)

**Problem**: Different OOB detection in traceTrajectory vs judgeShot.

**Root Cause**:
- traceTrajectory: used discrete (xmin, xmax)
- judgeShot: used continuous attackEndX
- No shared boundary authority

**Fix**:
- New: `src/field/FieldBounds.ts` (single source of truth)
- `fieldXMin()` / `fieldXMax()`: -400 / +400
- `attackEndX()`: directional endpoint
- Both functions now use FieldBounds

**Evidence**: All 5 test cases pass
- OOB detection unified
- Direction-aware boundaries correct
- Trajectory truncation consistent

---

### F3: Validation Asymmetry (CLOSED)

**Problem**: Validator sampled from Emitter only in direction A, creating unfair bias.

**Root Cause**:
- Validator.ts: hardcoded `dx = +h` regardless of team
- Team B functions validated only in positive direction
- Asymmetric coverage

**Fix**:
- `validateShootingFunction()`: Direction-aware sampling
- Team A: samples toward +x (right)
- Team B: samples toward -x (left)
- Symmetric coverage for both teams

**Evidence**: All 6 test cases pass
- Direction A/B symmetric sampling
- Both teams sample toward opponent
- Fairness restored

---

### F4: Geometry Obstruction (CLOSED)

**Problem**: 128-step discrete sampling missed narrow obstacles.

**Root Cause**:
- Relied on 128-point uniform sampling
- Narrow gaps < 3.125 units missed
- Gate 0 probe: y = x + sqrt(2) - 1e-6 passed through unit circle

**Fix**:
- New: `src/geometry/AnalyticIntersection.ts`
- Analytic intersection for all geometries:
  - lineCircleIntersection: quadratic solution
  - lineRectangleIntersection: boundary detection
  - lineSegmentIntersection: distance formula
  - polygonIntersection: edge-by-edge checking
- Sampling preserved as fallback

**Evidence**: All 9 test cases pass
- Original Gate 0 narrow crossing: BLOCKED ✓
- Tangent trajectories: BLOCKED ✓
- Near-tangent with clearance: NOT BLOCKED ✓
- All geometries covered

**PERMANENT RED REGRESSION**: Narrow crossing blocked

### F5: Emitter Semantic Drift (CLOSED)

**Problem**: CLI and Web had different Emitter selection semantics.

**Root Cause**:
- Web: manual selectEmitter/lockEmitter (correct)
- CLI judge.ts:360: unconditional autoSelectEmitters() in interactive mode
- CLI cli.ts:265: unconditional autoSelectEmitters() regardless of --auto
- Violated Match.ts:702-707 contract: "仅供无人值守演练与测试"

**Fix**:
- judge.ts: Removed line 360 unconditional auto-select
- cli.ts: Conditioned line 265 on `opts.auto === true`
- Interactive mode now prompts or errors
- Web session unchanged (already compliant)

**Evidence**: Code inspection verification
- Web: never calls autoSelectEmitters() ✓
- CLI: only in --auto mode ✓
- Judge: only in --auto mode ✓
- Contract compliance restored

### F7: Replay Determinism (CLOSED)

**Problem**: Replay and live execution produced different match IDs.

**Root Cause**:
- generateMatchId(): random generation on every call
- loadReplay(): passed loaded matchId as seed
- MatchEngine constructor: regenerated matchId, ignored opts.matchId

**Fix**:
- MatchEngine: Honor opts.matchId when provided
- loadReplay(): Pass original matchId to MatchEngine
- Replay now preserves exact matchId

**Evidence**: All 3 test cases pass
- Live: generates random matchId
- Replay: preserves original matchId
- matchId stability verified
