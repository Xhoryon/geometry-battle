## 3. ±18 Emitter 常量的精确分类

### 3.1 正式比赛语义

```text
双方上传/密封 → decoy preflight → 生成比赛地图
→ EMITTER_SELECT → 各队选初始点 → 各队锁定
→ 两个所选点移出战斗点 → READY
```

Emitter 只在**本场比赛内**固定、不可击杀、不计胜利目标。剩余点保留原 ID，不重编号。

[Match.ts:727–734](../src/core/Match.ts#L727-L734) 提供所选坐标，供输入、函数合法性与出招结算使用。正式输入调用显式传 Emitter，不依赖旧默认值。

### 3.2 ±18 既非 dead code，也非现行战斗锚点规则

[MapGenerator.ts:276–298](../src/map/MapGenerator.ts#L276-L298) 仍用固定 `EMITTERS` 预留布局空间；[430–453](../src/map/MapGenerator.ts#L430-L453) 检查其障碍/点间距；[366–377](../src/map/MapGenerator.ts#L366-L377) 将地图 Emitter 字段写进地图哈希。

这些是活跃的地图生成/校验/哈希约束。删除会影响地图或哈希，**不是** no-rule-diff 清理。

[InputProtocol.ts:78–114](../src/core/InputProtocol.ts#L78-L114) 保留可选旧默认值，低层测试常使用它；正式 Match 和本地工具显式传所选/decoy 锚点。Decoy preflight 取 decoy 地图中的点，并非普遍取 ±18。

**对任务书 A/B/C/D 的回答：不同用途活跃路径并存，附有过期注释。** Web 正式战斗用参赛者自选本场锚点；旧常量仍影响布局、哈希和默认工具。[Rules.ts:20–31](../src/core/Rules.ts#L20-L31)「不由任何人选择」已过时；不能据此说所有比赛仍从 ±18 发射。

### 3.3 入口差异

[operator/judge.ts:355–361](../src/operator/judge.ts#L355-L361) 与 [operator/cli.ts:264–266](../src/operator/cli.ts#L264-L266) 即使非自动路径也调用 `autoSelectEmitters()`，自动选择双方第一个候选并锁定。该 helper 的[契约](../src/core/Match.ts#L691-L709)明确仅限无人值守演练/测试。

审计使用全新临时槽位，给交互 judge 输入 `v`、`s`、`q`，未传 `--auto` 或双方算法，实际播种并进入 READY。相应 Web 筹备停在 EMITTER_SELECT。这是准备流程/决策权差异，不是第二套战斗引擎。

## 4. 计时、结果接收与回合终止

### 计时权威

- 起点：本队 GO 管道写入**之后**的单调时刻，[SandboxRunner.ts:1079–1104](../src/runner/SandboxRunner.ts#L1079-L1104)。
- 成功终点：结果文件 mtime 转换为单调时刻；不可用/超预算时回退宿主观察时刻，[1007–1017](../src/runner/SandboxRunner.ts#L1007-L1017)。
- 结果：首个被观察到且外壳 schema 合法的内容被冻结，后续文件版本不再考虑；DSL 合法性由 Match 后验。
- 正常情况下，结果接受后的退出/drain grace 不计入成功计算耗时。
- COUNTDOWN 是同步引擎推进，不是真实等待 3 秒。
- 浏览器计时、动画和 RoundMachine 的墙钟历史不参与计算耗时裁定。

### 已复现的 deadline 缺口

无害 solver 睡眠 650 ms，预算 500 ms，正常对照被判 `TIMEOUT`。仅将本探针宿主事件循环暂停 1000 ms，原 solver 就被接受，`success=true`、`computeTimeMs=1005.4385`。

迟到的 poll 设置 `pendingResult` 并撤销 timeout，却不要求最终采用的时间满足 deadline。[Match.ts:997–1007](../src/core/Match.ts#L997-L1007) 没有补验时间；[LocalPreflight.ts:256–266](../src/submission/LocalPreflight.ts#L256-L266) 有。该实验模拟宿主停顿，**不证明**参赛者总能制造这种停顿，但足以确认强制边界不成立。

临时文件写入 mtime 也不等于原子 rename 可见时刻。公开 README 已明确写 mtime；选择另一终点需要计时契约决策，不能静默修正。

### 什么结束一轮

双方 Runner 都结束，解析/校验两份输出，执行全部合法攻击，更新死亡点与无进展计数，生成回合和回放记录，再清除 START 授权及本轮输入缓存。随后进入 READY 或 MATCH_END。首份输出、首个命中或第一击造成全灭，都不单独结束该轮。

### 什么结束一场

所有攻击结算完毕后依次判断：

1. 单方全灭：另一方胜；双方全灭：同归于尽和局。
2. 否则，连续 20 轮零击杀：僵持和局。
3. 否则，第 60 轮：硬上限和局。

引擎仍保证**最迟**硬上限结束。错误描述是「第 60 轮一定将同轮全灭覆盖成 DRAW」。CLI 提前停止是另一种操作台行为。不能将有限回合保证扩大为任意平台崩溃/宿主停顿下的总墙钟时间保证。

## 5. 几何与数值规则边界

### 已复现的圆接触缺陷

合成场景使用未修改的 canonical parser、Validator 和 Judge：

- 圆心 `(0,0)`，半径 `1`。
- `f(x)=x+sqrt(2)-1e-6`。
- A Emitter `(-6,f(-6))`；B 活点 `(6,f(6))`。
- 独立计算圆心到直线距离 `0.9999992928932189 < 1`，因此直线确实穿圆。
- Validator 判合法；Judge 没有障碍截断，并击杀 `B1`。
- 对照 `f(x)=x+sqrt(2)-0.1` 正常阻挡，无击杀。

[Judge.ts:113–164](../src/core/Judge.ts#L113-L164) 在每个障碍物 x 投影上固定采样 128 段，极窄相交可能落在样点之间；只有先采到内部才二分。绘图自适应步长无法修复此搜索。使用真实穿越对照，避免只依赖精确相切的浮点解释。

这是已证明的低层战斗规则缺陷，不是生成赛事地图中的发生率统计。既有障碍和镜像套件仍通过：对称性测试可能在两边保留同一个错误。

### 冻结 spec 时必须保留的限定

- 连续、C²、凸性是数值检查，不是对全部实数 x 的解析证明。
- 网格从 Emitter 向远端推进；`span/h` 非整数时最后样点未必是精确远端。
- 中心差分可能计算攻击区间外的邻点。「区间外绝不求值」过强。
- 底层几何支持四类障碍；正式生成/输入目前使用矩形与圆。低层支持不自动构成正式输入契约。

## 6. 既有双边结算与 R4 的真实增量

Locked Attack Right 已保证双方合法攻击都执行，包括同归于尽。A 只攻击 B 的点，B 只攻击 A 的点；先手不会删除后手的敌方目标集合。本轮 AB/BA/tie 顺序无关性测试通过。

因此，「双方均可出招」「同归于尽判和」**不是**新的 R4 实验。未来应明确真正增量：删除先手元数据、总用同一快照、调整计时的竞争作用，或引入官方随机种子。本轮均未采纳。官方 deterministic solver-seed 契约、ruleset ID 和协议版本决定仍属未来任务；现有地图 seed 是另一项已实现能力。
