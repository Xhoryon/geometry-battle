- `src/map/MapGenerator.ts:196-235, 278-284`：障碍物先抽，再放 A 队点（`other=[emitterA]`），再放 B 队点（`other=[emitterB]`），
  同一个 RNG 顺序消费 ⇒ `generator(seed)` **不可能**逐 seed 镜像不变；只能检验**分布**对称。
- `src/core/InputProtocol.ts:82-84`：`points` 顺序 = 引擎自然序 A1..An、B1..Bm，即**放置顺序**，**没有**任何几何排序保证 ——

### 阶段 A（Track A）—— 镜像公平性测试栈 + Validator 网格锚点缺陷

**基线**：`feature/v1.4-platform-ux` @ `febf1c6`。接手时 load 1.5/1.7/2.2。

**目标**：把「平台对 Team A / Team B 是否镜像公平」变成永久、有判别力的测试（Level 1–6），并用一个可证明镜像的探针 solver 把引擎与选手隔离开审计。

**观察（改代码之前）**：
- Judge / Match 的全部队别分支都是 `dir = ±1` 参数化的镜像对（见 agent3 映射）；唯一形式上不对称的是 Validator 的采样网格从 `domain[0]` 起步 —— A 的 `domain[0]` 是 Emitter，B 的是 −20。
- 数值预探（`scratchpad/probe-hunt.ts`）：构造恰好 101 个拐点、首个拐点在 Emitter 后 0.004 处的正弦函数，A 数到 101（`CONVEXITY_LIMIT`），逐位镜像给 B 数到 100（合法）。tan 极点贴边（20+1e-7…3e-6）双方都非法但错误码不同（A `DISCONTINUOUS`，B `NOT_FINITE`/`NOT_C2`）。

**假设**：除 Validator 网格锚点外引擎逐位镜像；探针在 u 空间计算即可让镜像输入产出逐位镜像的函数，从而 Level 6 的任何差异都归因于平台。

**修改**：
- 新增 `tests/mirror-helpers.ts`（变换 M：x'=−x、A↔B、id 重标、障碍物保序、Emitter 互换、`mirrorAst` variable→neg(variable)、`selfCheck` 对合自检）。
- 新增 `tests/fixtures/algos/symmetry-probe/`（审计 fixture，**不得进 Tournament Mode**）：局部前进坐标 u（A: x−xe，B: xe−x），敌人按 (u,|Δy|,id) 排序，固定网格 K 的抛物线 64 点避障，退化到直线/水平线；无随机、无时间依赖。包哈希 `86f59fe2d6a6fcda654e3ddaeb773e0809cacb20e9f8a5056044bab7f25973ae`。
- 新增 `tests/mirror-fairness.ts`（10 用例，≈18 s，纯函数）与 `tests/mirror-match.ts`（1 用例，≈66 s，真沙箱，第二场把 `require('../src/map/MapGenerator').generateMapOrNull` 替换为返回 `mirrorMap(...)`，并断言引擎快照里的地图确为镜像）。
- 新增 `experiments/v1.4-fairness/README.md`（运行方式、探针设计、缺陷记录、A4 脚本占位）。
- **修改 `src/core/Validator.ts`**（31+/10−）：四条采样循环改为从 Emitter 出发沿进攻方向推进（`dir` 由 shooter.x 更近的区间端点推断；A 的采样点逐位不变，B 的为精确取负）；`countConvexityChanges` 增加可选参数 `dir`（默认 1，旧调用不变）；二阶差分改写为 `((fp + fm) − 2·f0)` 使镜像网格上逐位相同。

**为什么**：合法性是比赛规则的一部分，同一个镜像函数不能一边合法一边非法。采样锚点是实现细节，不改任何阈值（凸性 100、|f| 1e6、C²、500 ms、STALEMATE 20、HARD 60、ε 全部不动）。修复方向按任务书「锚在 Emitter、朝 attackEndX 走」。

**测试（按顺序、含负载）**：
1. 探针直跑 kit 示例：A 0.03 s / B 0.02 s；`validate-submission` PRE-FLIGHT PASS 双队（沙箱内 20.5 / 18.2 ms）。

**结果**：Level 1–6 全绿；Judge 对 5,812,510 个轨迹采样点 x/y 逐位镜像；Locked Attack Right 下 210 个 core 的击杀集合与各方 hits 与先手顺序无关（先手顺序本身不构成胜负偏差）。Validator 网格锚点是本轮唯一发现并修复的平台不对称。
