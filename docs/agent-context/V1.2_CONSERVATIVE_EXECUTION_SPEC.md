## 4.5 Preflight selected-Emitter correctness

A serious blind spot was found:

- the decoy Preflight world still used constant Emitter anchors;
- the actual match used participant-selected Emitters;
- an algorithm could therefore pass Preflight and become `INVALID` in the real match.

Reported fix:

```text
decoyEmitters
```

now uses the selected Emitter source of truth.

A related local self-check/generator path was also corrected.

Preserve the single-source anchor logic.

---

## 4.6 Obstacle visual overlap

The reported obstacle problem was primarily rendering-related rather than authoritative geometry overlap.

The previous renderer used only X-axis scaling for a circular world-space obstacle radius.

On non-square scaling this visually distorted circles.

The reported fix renders the mathematical circle correctly in screen space, potentially as an ellipse when screen X/Y scales differ.

Do not reopen map-generation semantics without evidence of real geometry overlap.

## 4.7 Filesystem path leakage

Browser-facing errors previously exposed host absolute paths through filesystem errors such as ENOENT.

Reported fixes sanitize those errors before returning them to the browser.

Preserve this guarantee.

## 4.8 Emitter documentation

Some participant-facing documentation incorrectly treated the Emitter as a hard-coded constant coordinate.

Reported fixes align docs with participant-selected Emitter semantics.

Keep anti-drift coverage so the constant-Emitter wording does not return.

# 22. V1.2 Emitter Model

In V1.2, the Emitter is chosen by the participant before the match.

Each side has a set of allowed initial own-team points.

The participant selects exactly one as the match Emitter.

After LOCK, it is fixed for the entire match.

The Emitter:

```text
is the mathematical function anchor
cannot be changed after lock
cannot be killed
does not become an ordinary combat target
remains fixed for the match
```

All eligible non-Emitter points remain Combat Points.
