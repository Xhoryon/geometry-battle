## 贯穿性约束（不是一次性任务）

- **MatchEngine 仍是唯一比赛判定来源。** 前端不得重新实现
  hit detection / obstacle・boundary 语义 / winner / timing / stalemate。
- **开发期用 targeted tests**，不要每阶段重跑全量。
- **每到稳定 milestone 更新 [PROJECT_STATE.md](PROJECT_STATE.md)** ——
  只记「当前有效事实」，不堆过程日志。
- **发现 context 文件与代码不一致时**：以代码 + 当前冻结规范为准核实，
  **修正文档后继续**，不要中途停下来等确认。
- 除非遇到**新的核心玩法冲突**，不中途等待用户确认。
