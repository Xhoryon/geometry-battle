## 未决问题

### 1. demo 的周期 2 极限环（非阻塞，规范 §93 排在后面）

加了绕行候选之后对局真的打起来了（击杀数 11→14 / 8→16 / 8→9），
但**三个种子仍全部以 `STALEMATE` 收场**：停滞段双方各在两条打不中的射击之间来回。
这是**策略**问题。`tests/demo-repro` 只保证「同样输入 → 同样结果」，**不保证结果能赢**。

### 2. `#12 改善 Web UI` 没有可判定的验收标准

已修掉具体缺陷（死 CSS 类名、大屏缺 `EMITTER_SELECT` 阶段名、两端源码预览统一、
大屏显示锚点），但「改善视觉与交互」是主观项。要把它变成可验收的东西，
需要人类给出至少一条可判定的标准。

### 3. 已修掉的一处假红

`fixed-emitter` 在一次全量里失败：`SLOW_SNIPER` 在 preflight 阶段超时。
单独重跑 12/12 通过 —— 是负载相关的假红。根因是该 fixture `time.sleep(0.4)`，
而预算是 500ms，只剩 100ms 余量，沙箱里 python 启动再加几十毫秒就踩线。
它只被当作「比 sniper 慢」的对照组，没有测试依赖 400 这个数值，
已改成 250ms（`81cf5a8`）。

### 4. 已知的非阻塞项

- ZIP 上传路径（`unzipToFiles` 的 stored / deflate 两个分支）**没有端到端覆盖**；
  `web/e2e` 走的是普通文件路径。
- 终端操作台（`src/operator/`）没有锦标赛模式 —— 它是操作员显式指定 `--a/--b`
  的入口，不存在「自动落回模板」的情形，因此**刻意未加**。
- `npm run e2e` 需要系统装有 Google Chrome（`playwright.config.ts` 里 `channel: 'chrome'`）。
- 错误码 `NOT_THROUGH_SHOOTER` 按规范 §21 **保留原名**（对外机器标识），
  只有消息正文用了现行术语 Emitter。

## demo 可复现性调查结果（规范 §81–§92）

```text
结论：**「直调 vs 沙箱分歧」不存在**。是复现输入本身错了。

直调 : 95ad922b5e4e1dbb × 10
沙箱 : 95ad922b5e4e1dbb × 10
两侧各自稳定且互相一致，并等于当年那一场实际提交的那一枪。
```

根因：此前那份复现输入由**回放帧**拼出，而回放帧里障碍物存的是平台**核心形态**
`{"type":"circle","center":[x,y]}`；协议真正下发的是 `{"type":"circle","cx":…,"cy":…}`。
`gb_world` 写的是 `ob.get("cx", 0.0)` —— **缺键静默退化成 0.0**，圆被挪到 x=0。
输入错了，答案却看起来完全合理。

修复与回归：

```text
fixture   tests/fixtures/demo-stall/  （停滞那轮的 public/reveal + source.json）
回归      tests/demo-repro            （fixture 哈希 == 引擎记录哈希；直调/沙箱各 10 次）
加固      gb_world 在 build_world 边界归一化障碍物，两种形状都收、认不出来就报错
```

**下一个要做的**（如果要继续 demo）：周期 2 极限环的策略改进。
