## 已完成的事

### 0. DEFLATE ZIP 覆盖（`b6298fc`，最终覆盖补丁）

此前浏览器演练只覆盖 **stored(0)** ZIP。`deflate(8)` 是解析器里另一条分支
（走 `DecompressionStream('deflate-raw')`），而它才是「用真实压缩工具打出来的包」
的常见形状 —— 之前完全没人走。

- fixture：`tests/fixtures/uploads/valid-deflate.zip`（Python `zipfile` 打出来
  的真 DEFLATE 包，带一层外层目录，3.1 KB，入库，不新增依赖）。
- 浏览器演练：Team B 改用它，并**一路打到终局**（上传 → 清单 → 源码审阅 →
  Preflight → 选锚点 → 锁定 → 揭晓 → START → 结算 → 终局 → 大屏 → 回放），
  证明解压出来的包不只是能装、而是**能参赛**。Team A 仍走 stored，两条分支都留。
- 事务性断言补强：坏 ZIP 替换那段改为比对**服务端权威的槽位哈希**
  （读 `/api/team/state` 的 `slot.hash`）替换前后是否相同 —— 要证明的是
  服务端认的那份没变，不是界面显示没变。
- 新增 `tests/web-zip`（不需要浏览器，因此没装 Chrome 的机器也守得住）：
  fixture 每条记录必须是 DEFLATE(8) 且压缩后真的变小（防止被重打成 stored）、
  用 Node 内置 zlib 解压后与源包逐字节一致。
- **变异检验**：把 `unzipToFiles` 的 deflate 分支改成直接抛错 → 演练在
  Team B 上传处变红 → 已还原。

### 1. 协议防漂移（`9eb2bd9`）

**官方** `reveal_state` 的圆形障碍物必须始终是文档写的扁平 `cx` / `cy`，
即使算法侧的兼容读取器（`gb_world`）两种形状都能吃。
新增的回归直接对着 `buildRevealState` 的真实输出断言，并与 `JSON_SCHEMA.md`
的字段表绑定，**不经过任何 fixture**。

为什么单独钉这一条：兼容读取器的存在会诱导「反正两边都能读，那把官方输出
也改成内部形态算了」—— 那会改掉字节，进而改掉 `public_state_sha256` /
`roundStateHash` 与所有历史回放的可复核性。已做变异检验。

### 2. 界面走查（`e97bb65`）

对照本波验收标准逐条改，并**用真实浏览器截图逐张看过结果**（不是只看代码）：

| 验收标准 | 落点 |
|---|---|
| 正常流程不需要终端 | 本来如此；四页全部点界面即可走完 |
| 每个阶段一个明显的下一步 | 参赛者四步进度条；裁判向导的单主按钮 + 不可点原因 |
| 竞技场是视觉中心 | 裁判台 340px 侧栏 + 其余全给舞台；大屏满幅 |
| 参赛者页「上传 → 校验 → 选锚点 → 锁定」明显 | sticky 四步条，**判据只来自服务端**；顺序摆正（先选后锁） |
| 裁判台清楚显示双方算法 / 就绪 / 锚点锁 / 下一步 | 顶部常驻双方状态条 + 向导主按钮 |
| 大屏立刻传达比赛状态 | 竞技场顶部阶段横幅，说的是人话 |
| 锦标赛模式不暴露内部测试算法 | 服务端四入口门禁（上一波已做） |
| 诊断信息不主导正常操作 | 走查中删掉了侧栏里那句常驻文档噪声 |

顺带修掉两个**设计纪律**问题：新增样式一度用了圆角 / 渐变 / `backdrop-filter`
（文件头明令禁止，已全部改回）；`button` 没有重置 UA 默认外观，导致
`<button class="link">`（两页文件清单）拖着浅色底，看起来像「选中了该行」。

### 3. ZIP 上传端到端（`fbf45af`）

ZIP 是唯一一条**在浏览器里**解析的输入路径，此前**没有任何端到端覆盖**。
新演练走完：平铺 ZIP 上传 → 带外层目录 ZIP 上传（钉住「外层目录必须剥掉」）
→ 只读浏览源码（与 ZIP 里的字节逐字一致）→ 裁判筹备（真实沙箱 Preflight）
→ 双方选锚点并锁定 → **坏 ZIP 当场报错** → **坏包不改动已装好的包**。

测试内自带最小 stored-ZIP 写入器（含 CRC32）。已做变异检验：把
`stripCommonRoot` 改成空操作后，带外层目录那条失败。
