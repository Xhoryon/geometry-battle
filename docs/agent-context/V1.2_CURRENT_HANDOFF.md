## 已完成的事

### 0. DEFLATE ZIP 覆盖（`b6298fc`，最终覆盖补丁）

此前浏览器演练只覆盖 **stored(0)** ZIP。`deflate(8)` 是解析器里另一条分支
（走 `DecompressionStream('deflate-raw')`），而它才是「用真实压缩工具打出来的包」
的常见形状 —— 之前完全没人走。

- fixture：`tests/fixtures/uploads/valid-deflate.zip`（Python `zipfile` 打出来
  的真 DEFLATE 包，带一层外层目录，3.1 KB，入库，不新增依赖）。
- 浏览器演练：Team B 改用它，并**一路打到终局**（上传 → 清单 → 源码审阅 →
  Preflight → 选锚点 → 锁定 → 揭晓 → START → 结算 → 终局 → 大屏 → 回放），
  证明解压出来的包不只是能装、而是**能参赛**。Team A 仍走 stored，两条分支都留。
- 事务性断言补强：坏 ZIP 替换那段改为比对**服务端权威的槽位哈希**
  （读 `/api/team/state` 的 `slot.hash`）替换前后是否相同 —— 要证明的是
  服务端认的那份没变，不是界面显示没变。
- 新增 `tests/web-zip`（不需要浏览器，因此没装 Chrome 的机器也守得住）：
  fixture 每条记录必须是 DEFLATE(8) 且压缩后真的变小（防止被重打成 stored）、
  用 Node 内置 zlib 解压后与源包逐字节一致。
- **变异检验**：把 `unzipToFiles` 的 deflate 分支改成直接抛错 → 演练在
  Team B 上传处变红 → 已还原。

### 1. 协议防漂移（`9eb2bd9`）

**官方** `reveal_state` 的圆形障碍物必须始终是文档写的扁平 `cx` / `cy`，
即使算法侧的兼容读取器（`gb_world`）两种形状都能吃。
新增的回归直接对着 `buildRevealState` 的真实输出断言，并与 `JSON_SCHEMA.md`
的字段表绑定，**不经过任何 fixture**。

为什么单独钉这一条：兼容读取器的存在会诱导「反正两边都能读，那把官方输出
也改成内部形态算了」—— 那会改掉字节，进而改掉 `public_state_sha256` /
`roundStateHash` 与所有历史回放的可复核性。已做变异检验。

### 3. ZIP 上传端到端（`fbf45af`）

ZIP 是唯一一条**在浏览器里**解析的输入路径，此前**没有任何端到端覆盖**。
新演练走完：平铺 ZIP 上传 → 带外层目录 ZIP 上传（钉住「外层目录必须剥掉」）
→ 只读浏览源码（与 ZIP 里的字节逐字一致）→ 裁判筹备（真实沙箱 Preflight）

### 4. 最终 RC 审计与阻断项修复（本波）

**独立 Final RC 审计**给出的结论是：

审计独立跑绿了 `typecheck` / `typecheck:web` / `npm test`（当时 36/36）/
`npm run e2e`（3 passed），并确认引擎权威、冻结语义、锦标赛四入口门禁、
上传事务性、两条 ZIP 分支、路径安全、回放只读、协议防漂移、渲染边界、
运行时整洁、Git/tag 安全**均未受影响**。

#### 它的发现

`/api/team/*` 与 `ws?topic=team-*` 的队别**完全由请求参数决定**，服务端没有任何
身份校验。实测后果：读到对方 reveal 前的 Emitter 选择、代对方改选/锁定锚点、
覆盖对方已提交的算法包、读对方源码。**需求 #7 在最基本的对抗下不成立。**

#### 修复时才发现的、更关键的一件事

`boards.ts` 的裁判板写着「Emitter 选择在这里给全（参赛者板才按队别裁剪）」，
而 `Match.ts` 的快照在队伍**一选就**填 `emitterChoice`（不受 `emittersRevealed()`
约束）。所以**只给参赛者加令牌根本关不掉这个洞** —— 打开 `/judge` 或其 API
就能看到对方的选择，还能代裁判 `reveal` / `start` / `reset` / `install`。
裁判面因此一并设了卡。

#### 做了什么

| 改动 | 位置 |
|---|---|
| 令牌签发与核验（HMAC 派生，无状态轮换） | 新增 `src/server/tokens.ts` |
| 裁判令牌 + 每队令牌（随 `matchId` 自动轮换） | `session.ts`、`boards.ts`、`protocol.ts` |
| HTTP 门禁（**精确路径**，排在协议层错误之后） | `http.ts` |
| WS 门禁（授权失败**绝不进 `handleConnection`**，关闭码 4401） | `ws.ts` |
| 裁判台入口带 `#t=`，banner 与自动打开同步 | `main.ts` |
| 「参赛者入口」面板（两条可复制链接，每场更新） | `JudgePage.tsx` |
| 令牌链路：fragment 读取 + 请求头 + WS query + 4401 停止重连 | `client.ts`、`AccessNotice.tsx` |
| P2-1 上传 fs 异常不再回宿主绝对路径 | `upload.ts` |
| P2-3 前端 ZIP 解压加流式体积上限 + 逐条 CRC | `web/src/api/zip.ts` |

**没有**碰 `src/core/`（引擎权威与冻结语义），**没有**把令牌下沉到
`MatchSetupUI` / 引擎 —— 鉴权只做在 HTTP/WS 边界，因此 `npm run judge`
与 `tests/operator-e2e.ts` 完全不受影响（实测 `src/operator/` 零 HTTP 调用）。

#### 两个值得记住的坑

1. **WS 鉴权的位置是硬约束。** `handleConnection` 第一行就 `send(hello)` +
  `send(整块 board)`。把鉴权写进它开头，裁判板会在关闭**之前**完整推给未授权连接，
  而客户端确实收到 4401 —— **测试照样绿**。`tests/team-auth.ts` 因此断言
  「关闭前一个字节都不发」，并用变异检验确认过这条断言真的有牙齿。
2. **门禁顺序被既有用例钉死。** 必须排在 `readJsonBody` 之后，且必须走精确路径。
   `tests/web-server.ts` 那四条边界断言（403/415/404/400）**一行未改** ——
  它们迁移后自动变成「门禁没有抢占协议层错误」的正面回归。

#### 新增回归

- `tests/team-auth.ts`（第 37 个套件）：无令牌 / 错队令牌 / 裁判面无令牌 /
  畸形令牌不 500 / 换场后旧令牌失效 / WS 未授权零字节 / **公开面仍须匿名可用的反向对照**。
- `tests/web-zip.ts` 增 4 条：直接 import 被测解包器（去掉 DOM-only 的 `Blob` 之后
  平台 tsconfig 也能编译它）、CRC 不匹配被拒、**声明值撒谎的 deflate 炸弹被流式上限拒**。
- `tests/server-team.ts` 增 1 条：畸形清单被拒且响应不含宿主路径。
- e2e 增：核对「参赛者入口」面板链接、换场后链接必须更新、损坏 ZIP 当场可见。
