# V1.5 Gate 0 — Startup, Security and Frontend Baseline

## 1. Decision and scope

**STOP — NOT READY TO FREEZE V1.5.0 SPEC.** This report completes the requested baseline investigation, not V1.5 implementation or release acceptance. The Master Plan explicitly authorizes only Gate 0 and requires stopping on active rule discrepancies or incorrectly assumed security enforcement.

Audited release: public `v1.4.3`, commit `f6b2a4677e67b8797c6e52a9947b5ddeecab9be3`, tree `b70cae7cde3434bd8d4923191bf8af43d9b1514f`, checked on 2026-09-14. The [Rule Baseline](V1.5_RULE_BASELINE.md) contains provenance and the ten-rule cross-layer matrix.

No production code, tests, competition rules, existing documentation or input plan was changed. No commit, push, tag, release or remote write was performed. Only new audit documents and sanitized evidence are deliverables. Implementation, R4 selection, and remediation remain unapproved.

## 2. Startup baseline

| Entry | Actual behavior | Important boundary |
|---|---|---|
| `npm run app` | Always builds Vite frontend, then runs TypeScript server; prepares default slots; listens on `127.0.0.1`; attempts browser opening | Build failure stops the shell chain. Listening successfully does not prove tournament/security eligibility |
| `npm run app:dev` | Starts the same backend, then launches Vite HMR with the actual backend port | `--dev` does **not** set `tournamentMode=false` or select a separate Runner security policy; no browser opening in this branch |
| `npm run judge` | Interactive terminal judge, optional unattended mode, default slot seeding | Even interactive `s` automatically selects/locks both Emitters; no Web bundled-package eligibility gate |
| `npm run operator` / `npm start` | Same operator CLI; loads slots, preflights, auto-selects Emitters; waits before rounds unless automatic | Not the Web launcher. Exposes timeout override and an early-stop round count |
| `npm run tournament` / `npm run dev` | **Absent** | V1.5 targets, not existing commands |

Evidence: [package.json:7–20](../package.json#L7-L20), [server/main.ts:70–132](../src/server/main.ts#L70-L132), [144–235](../src/server/main.ts#L144-L235), [operator/judge.ts:137–245](../src/operator/judge.ts#L137-L245), [355–361](../src/operator/judge.ts#L355-L361), [operator/cli.ts:191–309](../src/operator/cli.ts#L191-L309).

### Ports, directories and recovery

- Default backend port is 17800. `EADDRINUSE` retries with port 0, not an incremental port sequence. Returned/printed URLs use the actual port. Other bind failures propagate.
- Default slots are platform-root `runs/slots`; canonical `algorithms` are seeding fixtures, not the intended live submission directory.
- Server seeds only when no explicit slot root was provided. Operator seeds when the resolved root equals its default. Judge seeds any specified root. Seeding treats a missing `solver.py` as incomplete and may replace that team directory; it is not a promise never to replace any existing directory.
- Artifacts default to process-cwd `artifacts`; frontend output is platform-root `web/dist`; sandbox root defaults to system temp. These are different roots, not one runtime store.
- Direct server startup can listen without frontend dist and serve 503 for the page. Browser-open failure is non-fatal.
- SIGINT/SIGTERM and fatal fail-stop handlers exist. However, session close does not cancel an active automatic match; Vite is not explicitly terminated by the shutdown handler. Normal Runner cleanup exists, but setup/READY-failure paths lack the same cleanup coverage.
- Persist failures can be swallowed while the match continues. Individual JSON replacements are atomic, not a three-file transaction. Restart does not reconstruct an in-progress MatchEngine.

### Warning versus blocker

| Check | Existing consequence |
|---|---|
| Bad HTTP Host/Origin, wrong role capability, malformed protocol | Request rejected |
| Invalid package/failed installation preflight | Installation rejected |
| Missing sealed packages or failed match preflight | Match creation rejected |
| Missing Emitter locks / missing round START authorization | Engine refuses the relevant progression/computation |
| Sealed-package content mismatch before a round | Computation rejected and tamper event recorded |
| Known bundled hash in Web Tournament Mode | Rejected at Web submission/use-slot/prepare entry points |
| Python version mismatch | Diagnostic/audit only; this is explicitly disclosed in the public README |
| Missing sandbox mechanism | **No formal blocker: Runner chooses plain Python** |
| `runtime.ok`, isolation flags, slot READY | Not a complete security/readiness certificate |
| Missing dist, failed browser opening, some slot preparation errors | Not a server-listening blocker |

## 3. Sandbox and submission baseline

### Existing defenses worth preserving

The shared chain is:

```text
browser files / operator directory
→ package inspection → staging copy + hash check → decoy installation preflight
→ slot replacement → match-specific sealed copy → bilateral match preflight
→ map + Emitter locks → round input binding → verifySeal
→ fresh per-side sandbox → READY/GO → bounded diagnostics + result.json
→ canonical DSL validation → Judge → persisted artifacts
```

Package sealing already exists. It is not a brand-new V1.5 requirement. Current protection combines per-file/content hashes, copied sealed packages, phase guards, round-start rehash and OS sandbox write denial. It is not an immutable storage service or a signed attestation.

| Property | Actual enforcement / limitation |
|---|---|
| Network | macOS profile denies `network*`; meaningful only when that backend runs |
| Filesystem | Broad read permission followed by deny paths for user/repository/slots/artifacts/sandboxes; own sandbox re-allowed. This is not a strict runtime-only read allowlist |
| Environment | Fresh minimal environment; host credential variables are not inherited. Some OS launcher variables are documented additions |
| Process isolation | Detached process group; whole-group SIGKILL; sandbox denies fork. Not a separate UID, VM, or thread quota |
| Memory | Best-effort shell limit plus 60 ms host RSS polling; sampling errors are ignored. Not a continuously enforced 512 MB allocation ceiling |
| CPU/thread | `cpuQuota=1` is declaration; library thread environment variables are set to 1. Ordinary Python thread creation is not blocked |
| Time | Per-side GO/mtime accounting with host timers; confirmed late-result gap in the Rule Baseline |
| Diagnostics | stdout overflow fails; stderr retained data is capped. Neither is the official result channel |
| Result | First observed schema-valid `output/result.json`; no pre-read result-file byte cap or total work/output disk quota |
| Fresh rounds | New directories and normal cleanup; READY/setup failure cleanup and upload staging cleanup are incomplete |
| Package policy | 8 MiB and 256-file limits plus extension policy; local traversal reads before final total checks. No complete V1.5 safe file-type/depth/single-file policy yet |

Evidence: [SandboxRunner.ts:305–422](../src/runner/SandboxRunner.ts#L305-L422), [526–534](../src/runner/SandboxRunner.ts#L526-L534), [679–721](../src/runner/SandboxRunner.ts#L679-L721), [838–904](../src/runner/SandboxRunner.ts#L838-L904), [991–1067](../src/runner/SandboxRunner.ts#L991-L1067), [1138–1247](../src/runner/SandboxRunner.ts#L1138-L1247); [Package.ts](../src/submission/Package.ts), [Slot.ts](../src/submission/Slot.ts).

### Runtime identity is incomplete

[Runtime.ts:143–170](../src/submission/Runtime.ts#L143-L170) checks probe success, Python version/implementation and enumerated frozen package entries. It does not compare platform; the frozen package list is empty. Host detection is not sandbox import verification, and fixed executable path is not binary identity.

A synthetic observation with the frozen Python/version but platform `linux` returned `ok=true`. A real macOS sandbox probe successfully created and joined one ordinary worker thread. These are narrowly scoped results: the first is a pure-function false green, not a test run on Linux; the second proves no general single-thread limit, not measured multi-core advantage.

Session runtime status is captured at construction, while engine match creation probes again for audit. The badge and audit can represent different observations. No `TournamentEligibility`, runtime profile ID, security self-test contract or unified Doctor exists.

### Confirmed cross-team raw-upload gap

[upload.ts:112–137](../src/server/upload.ts#L112-L137) creates a raw upload copy in the OS temporary root. [session.ts:263–282](../src/server/session.ts#L263-L282) neither cleans it nor registers it as a formal denied source path. [Match.ts:1398–1406](../src/core/Match.ts#L1398-L1406) denies the known source/slot/artifact paths, not these raw copies. The Runner keeps the same user identity; mode 0700 therefore does not isolate the copy from that process.

**Synthetic verification:** this audit uploaded a newly generated B package containing a harmless marker, captured only that newly created path without enumerating other uploads, then submitted an A fixture that could pass installation preflight only after reading that exact marker. B upload succeeded, its raw copy remained, and A installation preflight succeeded with no error. Test-created raw copies were removed afterwards.

This proves readability of a known opponent raw-upload path under the tested default macOS layout. It does not establish arbitrary path discovery, or claim that actual contestant source/host secrets were read. It is separate from API capability checks, which passed their existing tests.

## 4. Frontend workflow and authority baseline

### Roles and visible steps

| Role | Current top-level behavior |
|---|---|
| Judge | Seven presentation steps: Match Setup → Algorithm Ready → Emitter Lock → Ready → Reveal → Live → Result. Advanced exposes lower-level commands |
| Team | Six steps: Submit → Validate → Preflight → Select → Lock → Wait; source/package details and point selection |
| Spectator | Anonymous, no match-command controls; score, arena, phase, timing, attacks and final result |
| Replay | Persisted frames only; playback, step selection and 0.5×/1×/2× speed; no Judge execution |
| Home | Role/capability entry and recent replays, not an environment dashboard |

Sources: [judgeWizard.ts](../web/src/pages/judgeWizard.ts), [teamSteps.ts](../web/src/pages/teamSteps.ts), [replayPlayer.ts](../web/src/pages/replayPlayer.ts), [spectatorView.ts](../web/src/pages/spectatorView.ts).

### START is three different operations

1. `start` creates the map and enters EMITTER_SELECT after sealed packages/preflight.
2. `start-round` grants round authorization and enters COUNTDOWN; compatible READY/PUBLIC paths first finish reveal preparation.
3. `compute` checks authorization, phase, inputs and seal, then executes algorithms.

`run-to-end` and its button share [runToEndBlocker](../src/server/boards.ts#L373-L380) and use the same engine methods. Other action projections duplicate some checks. No confirmed case showed that changing a frontend `enabled` value bypasses the existing engine authorization. **Missing formal security eligibility is not the same as bypassing a complete eligibility system that already exists.**

### Confirmed projection and information-boundary discrepancies

- After successful `useSlot('A')`, phase is UPLOAD_A. The server advertises `prepare.enabled=true`, but `prepareMatch()` restarts at A and returns `当前阶段 UPLOAD_A 不允许上传 Team A`. Lower-level continuation may recover; this is not an unavoidable whole-platform deadlock.
- Successful Web preparation yielded `EMITTER_SELECT`, round 0, with **2 obstacles already present in the spectator arena**. Anonymous spectator WS sends that projection. Team's live UI says obstacles are not public before reveal. This needs a role-visibility decision; it does not prove contestant code executes before GO or receives an early official reveal file.
- Slot READY means current structural validity, installation preflight comes from a historical record, match preflight refers to the sealed match copy, and phase READY means both Emitters are locked. They must not collapse into one “safe to start” badge.
- Team cards/source preview can mix current-slot identity with sealed-match identity. The installation preflight record is not checked against the current slot hash before displaying PASS.
- A global `lastError` can reach both team boards. Static tracing shows package mismatch details can enter that string; no live confidential diagnostic was exposed in this audit.

### Errors, accessibility and replay

Action labels/hints and round/replay errors already support keys and parameters. Many submission/command failures remain raw Chinese strings. `CommandResult` does not provide the proposed stable error taxonomy with bilingual human/action/technical fields.

Native disabled controls, visible focus, descriptive text, keyboard alternatives and reduced-motion support exist. Existing viewport coverage targets 1024×768, 1280×720, 1440×900 and 1920×1080 in both languages. This audit did **not** rerun browser E2E, keyboard-only or screen-reader tests; source coverage is not fresh browser evidence.

Replay loading checks compatibility and terminal result classification, but does not prove frame/hash/package/runtime authenticity. No Verified Match contract exists. Anonymous replay data is a separate transport from SpectatorBoard; an unrendered field is not an untransmitted field. Replay verification and public/private diagnostic separation must be explicit future contracts.

## 5. Confirmed inconsistency register

Severity below is a **provisional Gate 0 remediation priority**, not the outcome of a V1.5.3 full independent security audit. `DYNAMIC` means a bounded probe was run; `STATIC` means the traced source proves the stated branch, without claiming an executed exploit.

| ID | Priority | Finding and evidence level | Required disposition |
|---|---|---|---|
| G0-01 | P0 | Raw opponent upload copy readable by A installation preflight at a known synthetic path — DYNAMIC | Fix upload lifetime/read isolation with a synthetic regression; re-evaluate formal safety before accepting untrusted submissions |
| G0-02 | P1 | Backend unavailable selects plain Python; isolation flags remain true — STATIC | Make formal unavailability fail closed and report actual evidence; do not disable the real sandbox to test this |
| G0-03 | P1 | 500 ms late result accepted after host event-loop pause — DYNAMIC | Freeze timing acceptance contract, then repair deadline enforcement and add delayed-host regression |
| G0-04 | P1 | General single-thread limit is absent; CPU quota only declared — DYNAMIC thread / STATIC CPU | Decide enforceable runtime profile; do not label library environment settings as OS quotas |
| G0-05 | P1 | Narrow circle crossing not blocked, downstream point killed — DYNAMIC | Approve a targeted baseline correctness repair, with independent analytical and mirror controls |
| G0-06 | P1 | Interactive terminal auto-selects Emitters and accepts seeded bundled packages unlike default Web — DYNAMIC plus STATIC | Decide terminal formal status; align or clearly limit the interface without silently altering strategy |
| G0-07 | P1 | Pre-reveal spectator obstacles conflict with live Team visibility wording — DYNAMIC projection plus STATIC anonymous transport | Freeze human-role versus algorithm-input visibility; neither choice is automatically a cosmetic fix |
| G0-08 | P2 | Partial-prepare action advertised enabled but rejected — DYNAMIC | Shared resumable action policy or correct projection, with partial-state tests |
| G0-09 | P2 | Runtime platform mismatch can return OK; status is incomplete/cached — DYNAMIC pure function plus STATIC | Report actual effective identity and observation time; preserve warning/blocker distinction |
| G0-10 | P2 | Legacy Emitter comments, hard-limit precedence wording, and active fairness report disagree with current code — STATIC | Record accurate baseline and restore evidence-based public descriptions without rewriting historical artifacts |
| G0-11 | P2 | Cleanup/storage failure paths and slot/sealed/preflight identity are weaker than general claims — STATIC | Lifecycle/transaction and status-truthfulness work; specify what was not dynamically tested |

Additional scoped design gaps: no result-file pre-read byte cap; no total temporary-write quota; best-effort memory sampling; no full import allowlist; no authenticated replay proof; no running-match recovery. They are not all newly introduced bugs, and absence of a future V1.5 capability alone is not a V1.4 violation.

Package commit rollback after post-replacement validation, copy-after-rehash races and global diagnostic strings were statically identified for targeted follow-up. They were not dynamically exercised here; do not present them as verified attacks or broaden the scope into a full exploit campaign.

## 7. Proposed V1.5.0 scope — not frozen or authorized

### Prerequisite: explicit baseline disposition

Address G0-01–G0-07 and clarify G0-10 before claiming zero critical drift. This does not mean automatically reopening a V1.4 documentation-only release. Use a separately approved V1.5 baseline-remediation scope; preserve old release trees and historical evidence. Timing and geometry corrections need their own attribution and regressions, not concealment inside UX commits.

### V1.5.0 IN after prerequisite review

1. Thin TournamentLauncher around existing `startServer`, with `npm run tournament` and a clearly separated development entry.
2. Structured Doctor with PASS/WARN/BLOCK, actual Node/Python/backend/filesystem/frontend/port observations and actionable errors.
3. One authoritative eligibility/action-policy projection, reused at execution time; UI unknowns remain unknown rather than green.
4. Judge SETUP/READY/LIVE/RESULT and Team Upload/Verify/Lock/Ready as **presentation aggregation**, without changing engine phases or combat semantics.
5. Separate current-slot, sealed-match, preflight, runtime/security and persistence statuses; modular readiness/cards/controls/technical details.
6. Bilingual error keys/parameters plus role-filtered diagnostics; keyboard/focus/disabled-reason and four-viewport acceptance.
7. Explicit startup ownership/cleanup, actual-port reporting, browser failure recovery. Build reuse is optional after measurement.

### OUT

New DSL, arbitrary geometry/rule redesign, removal of locked attack rights, deterministic seed requirement, R4 simultaneous adoption, cross-platform formal support, full sandbox rewrite, or a Verified Match badge without verification. V1.5.1 remains the secure-backend/profile/resource-hardening stage; V1.5.2 requires an evidence-based ruleset/protocol decision; V1.5.3 owns comprehensive RC campaigns.

**No implementation proceeds from this report alone.** Review the baseline, authorize the remediation/spec-freeze step, then evaluate Gate 0 again.
