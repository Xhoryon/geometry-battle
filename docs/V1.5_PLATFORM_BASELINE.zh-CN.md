# V1.5 Gate 0 — 启动、安全与前端基线

## 1. 结论与范围

**STOP — NOT READY TO FREEZE V1.5.0 SPEC。** 本报告完成基线调查，不代表 V1.5 实现完成或发布验收。Master Plan 明确仅授权 Gate 0，并要求遇到活跃规则差异或被误认为已强制的安全能力时停止。

被审对象：公开 `v1.4.3`，commit `f6b2a4677e67b8797c6e52a9947b5ddeecab9be3`，tree `b70cae7cde3434bd8d4923191bf8af43d9b1514f`，于 2026-09-14 核验。[规则基线](V1.5_RULE_BASELINE.zh-CN.md)记录来源与十项跨层规则矩阵。

没有修改生产代码、测试、比赛规则、既有文档或输入任务书；没有 commit、push、tag、release 或远端写入。本轮只交付新审计文档和脱敏证据。实现、R4 选择和修复仍未获授权。

## 2. 启动基线

| 入口 | 实际行为 | 关键边界 |
|---|---|---|
| `npm run app` | 每次构建 Vite 前端，再运行 TypeScript server；准备默认槽位；监听 `127.0.0.1`；尝试开浏览器 | 构建失败阻断命令链；监听成功不证明赛事/安全资格 |
| `npm run app:dev` | 先启动相同后端，再向 Vite HMR 传实际后端端口 | `--dev` **不会**设 `tournamentMode=false`，也不选择另一套 Runner 安全策略；此分支不自动开浏览器 |
| `npm run judge` | 交互终端裁判，可无人值守，默认播种槽位 | 交互 `s` 也自动为双方选锁 Emitter；没有 Web bundled-package 资格门禁 |
| `npm run operator` / `npm start` | 同一 operator CLI，载槽位、preflight、自动选 Emitter；非自动时每轮等待 | 不是 Web 启动入口；可覆盖 timeout、设提前停止回合数 |
| `npm run tournament` / `npm run dev` | **不存在** | 是 V1.5 目标，不是现有命令 |

证据：[package.json:7–20](../package.json#L7-L20)、[server/main.ts:70–132](../src/server/main.ts#L70-L132)、[144–235](../src/server/main.ts#L144-L235)、[operator/judge.ts:137–245](../src/operator/judge.ts#L137-L245)、[355–361](../src/operator/judge.ts#L355-L361)、[operator/cli.ts:191–309](../src/operator/cli.ts#L191-L309)。

### 端口、目录与恢复

- 后端默认 17800。遇 `EADDRINUSE` 改用端口 0，不是递增查找。返回/打印实际 URL；其他监听异常向上传播。
- 默认槽位是平台根的 `runs/slots`；canonical `algorithms` 是播种 fixture，不是正式投递目录。
- Server 仅未显式传槽位根时播种；operator 在解析后的根等于默认根时播种；judge 对任意根播种。播种以缺少 `solver.py` 视为未完成，可能替换该队目录；不能说「已有目录绝不替换」。
- 产物默认位于进程 cwd 的 `artifacts`；前端位于平台根 `web/dist`；沙箱默认系统临时目录。它们不是统一 Store。
- 直接启动 server 时缺 dist 仍可监听，页面回 503；开浏览器失败不致命。
- 已有 SIGINT/SIGTERM 与 fatal fail-stop。但 session close 不取消正在自动推进的比赛，shutdown 不显式终止 Vite。正常 Runner 有清理，setup/READY 失败路径没有同等覆盖。
- 落盘失败可能被忽略而比赛继续。各 JSON 分别原子替换，不是三文件事务。重启不会重建进行中的 MatchEngine。

### Warning 与 blocker

| 检查 | 现有效果 |
|---|---|
| HTTP Host/Origin 错误、角色 capability 错误、协议非法 | 请求拒绝 |
| 包不合法/安装 preflight 失败 | 安装拒绝 |
| 缺双方密封包或本场 preflight 失败 | 建赛拒绝 |
| Emitter 未锁/本轮未 START 授权 | 引擎拒绝相应推进/计算 |
| 回合前密封包内容不一致 | 拒绝计算，记录 tamper 事件 |
| Web Tournament Mode 命中已知内置包哈希 | 提交、使用槽位、prepare 入口拒绝 |
| Python 版本 mismatch | 仅诊断/审计；公开 README 已明确说明 |
| 缺沙箱机制 | **没有正式 blocker，Runner 选择裸 Python** |
| `runtime.ok`、isolation flags、slot READY | 都不是完整的安全/readiness 认证 |
| 缺 dist、开浏览器失败、部分槽位准备错误 | 不阻止 server 监听 |

## 3. 沙箱与提交基线

### 应保留的既有防线

```text
浏览器文件 / 操作台目录
→ 包检查 → staging 副本和哈希复验 → decoy 安装 preflight
→ 替换槽位 → 本场密封副本 → 双方本场 preflight
→ 地图和 Emitter 锁定 → 回合输入绑定 → verifySeal
→ 双方全新沙箱 → READY/GO → 有界诊断和 result.json
→ canonical DSL 校验 → Judge → 产物落盘
```

Package sealing 已存在，不是 V1.5 从零添加。现有保护由文件/包哈希、密封副本、阶段门禁、回合前 rehash 和 OS 写拒绝共同构成，不是强不可变存储服务或签名证明。

| 属性 | 实际强制方式/限制 |
|---|---|
| 网络 | macOS profile 拒绝 `network*`，仅在该后端实际运行时成立 |
| 文件读取 | 广泛允许后再拒绝用户/仓库/槽位/产物/沙箱等目录，最后重放行本队；不是严格 runtime-only 读白名单 |
| 环境 | 新建最小环境，不继承宿主凭据变量；文档说明少量 OS launcher 自注入变量 |
| 进程 | 独立进程组、整组 SIGKILL、sandbox 禁 fork；不是独立 UID、VM 或线程配额 |
| 内存 | best-effort shell limit 加 60 ms RSS 采样，采样失败忽略；不是持续强制的 512 MB 分配上限 |
| CPU/线程 | `cpuQuota=1` 是声明，库线程环境设 1；普通 Python 线程可创建 |
| 时间 | 双方 GO/mtime 计时，依赖宿主 timer；规则基线已确认迟到接收缺口 |
| 诊断 | stdout 超限失败，stderr 留存有上限；均不是正式结果通道 |
| 结果 | 首个观察到的 schema-valid `output/result.json`；读取前无结果字节上限，无 work/output 总磁盘配额 |
| 跨轮新环境 | 新目录和正常清理；READY/setup 失败及原始上传清理不完整 |
| 包政策 | 8 MiB、256 文件及扩展名政策；本地遍历先读取再检查总量；尚非完整 V1.5 文件类型/深度/单文件政策 |

证据：[SandboxRunner.ts:305–422](../src/runner/SandboxRunner.ts#L305-L422)、[526–534](../src/runner/SandboxRunner.ts#L526-L534)、[679–721](../src/runner/SandboxRunner.ts#L679-L721)、[838–904](../src/runner/SandboxRunner.ts#L838-L904)、[991–1067](../src/runner/SandboxRunner.ts#L991-L1067)、[1138–1247](../src/runner/SandboxRunner.ts#L1138-L1247)；[Package.ts](../src/submission/Package.ts)、[Slot.ts](../src/submission/Slot.ts)。

### Runtime 身份不完整

[Runtime.ts:143–170](../src/submission/Runtime.ts#L143-L170) 只核对探测成功、Python 版本/实现、冻结包列表项；不比较 platform，冻结包列表为空。宿主探测不是沙箱 import 验证，固定启动路径也不是二进制身份。

合成观测中，冻结 Python/版本配上 `linux` 返回 `ok=true`。真实 macOS 沙箱中，普通 worker thread 能创建并 join。限定：前者是纯函数假绿，不是 Linux 实机测试；后者证明无通用单线程限制，不是多核优势测量。

Session 构造时保存 runtime，engine 建赛时又单独探测写审计，徽章与审计可能对应不同观测。尚无 `TournamentEligibility`、runtime profile ID、安全自检契约或统一 Doctor。

### 已确认的跨队原始上传缺口

[upload.ts:112–137](../src/server/upload.ts#L112-L137) 在 OS 临时根创建原始上传副本。[session.ts:263–282](../src/server/session.ts#L263-L282) 不清理，也未登记为正式拒绝读取的源目录。[Match.ts:1398–1406](../src/core/Match.ts#L1398-L1406) 拒绝已知源/槽位/产物，不包含这些 raw copies。Runner 不切换用户身份，因此 0700 不能隔离同 UID 算法进程。

**合成验证：**本轮上传一份带无害标记的新 B 包，只捕获本次新建路径、不枚举其他上传；随后提交 A fixture，只有读取该标记后才会通过安装 preflight。B 上传成功、原始副本保留，A 安装 preflight 成功且无错误。之后删除探针创建的 raw copies。

这证明测试所用默认 macOS 布局下，已知对手 raw-upload 路径可读；不证明任意路径发现能力，也未读取真实选手源码或宿主秘密。它与已通过既有测试的 API capability 检查是不同层的边界。

## 4. 前端工作流与权威状态

### 角色与步骤

| 角色 | 现有顶层行为 |
|---|---|
| Judge | 七格：比赛筹备 → 算法就绪 → 锚点锁定 → 就绪 → 揭晓 → 进行中 → 终局；Advanced 暴露低级动作 |
| Team | 六步：上传 → 校验 → Preflight → 选择 → 锁定 → 等待；包/源码详情与点选择 |
| Spectator | 匿名，无比赛命令；分数、场地、阶段、时间、攻击与终局 |
| Replay | 只读落盘帧；播放/选帧/0.5×、1×、2×；不执行 Judge |
| Home | 角色/capability 入口与最近回放，不是环境诊断面板 |

来源：[judgeWizard.ts](../web/src/pages/judgeWizard.ts)、[teamSteps.ts](../web/src/pages/teamSteps.ts)、[replayPlayer.ts](../web/src/pages/replayPlayer.ts)、[spectatorView.ts](../web/src/pages/spectatorView.ts)。

### 三种不同的 START

1. `start`：密封包/preflight 满足后建地图，进入 EMITTER_SELECT。
2. `start-round`：授予本轮执行权，进入 COUNTDOWN；兼容 READY/PUBLIC 时先补齐揭晓准备。
3. `compute`：核对授权、阶段、输入和 seal，再执行算法。

`run-to-end` 与按钮共用 [runToEndBlocker](../src/server/boards.ts#L373-L380)，最终调用同一引擎。其他动作投影重复部分条件。没有确认案例表明修改前端 enabled 可越过既有引擎授权。**缺少完整安全资格模型，不等于绕过一个已经存在的完整资格模型。**

### 已确认的投影与信息边界差异

- 成功 `useSlot('A')` 后为 UPLOAD_A，server 仍显示 `prepare.enabled=true`，但 `prepareMatch()` 从 A 重来，返回「当前阶段 UPLOAD_A 不允许上传 Team A」。低级动作可能继续恢复，不是所有场景永久死锁。
- Web prepare 成功后为 EMITTER_SELECT、round 0，spectator arena 已有 **2 个障碍物**；匿名 spectator WS 下发该投影，而 Team 活跃文案说揭晓前不公开。需要决定角色可见性，不能据此说算法 GO 前已运行或提前收到正式 reveal 文件。
- Slot READY＝当前结构有效；安装 preflight＝历史记录；本场 preflight＝密封副本通过；phase READY＝双方 Emitter 已锁。不可合成一个「安全开赛」徽章。
- 队卡和源码预览可能混用当前槽位与本场密封身份。显示安装 preflight PASS 时没有核对记录哈希与当前槽位哈希一致。
- 全局 `lastError` 可进入两队 board；静态链表明包不一致诊断可进入该字符串。本轮没有暴露真实私密诊断。

### 错误、无障碍与回放

动作标签/提示、回合/回放错误已支持 key+params；不少提交/命令失败仍是原始中文字符串。`CommandResult` 没有目标中的稳定 taxonomy、中英 human/action/technical 字段。

已有原生 disabled、可见焦点、描述文字、键盘替代和 reduced motion。既有视口测试覆盖两语言 × 1024×768、1280×720、1440×900、1920×1080。本轮**未重跑浏览器 E2E、纯键盘或读屏测试**；源码覆盖不是新鲜浏览器证据。

Replay 加载检查兼容性和终局分类，不证明帧/哈希/包/runtime 的真实性。尚无 Verified Match 契约。匿名 replay 与 SpectatorBoard 是不同载荷；未渲染不等于未传输。回放验证和公私诊断分离必须作为未来明确契约。

## 5. 已确认不一致清单

分级是 **Gate 0 临时修复优先级**，不是 V1.5.3 完整独立安全审计结论。`DYNAMIC` 表示运行过有界探针；`STATIC` 表示源码调用链足以证明所述分支，不代表执行过攻击。

| ID | 优先级 | 问题及证据等级 | 所需处置 |
|---|---|---|---|
| G0-01 | P0 | A 安装 preflight 可读已知合成路径下的 B 原始上传副本 — DYNAMIC | 修复上传生命周期/读取隔离，加入合成回归；重新评估接受不可信提交的资格 |
| G0-02 | P1 | 缺 backend 时裸 Python，isolation flags 仍 true — STATIC | 正式模式 fail closed，报告实际证据；不要关闭真实沙箱来验证 |
| G0-03 | P1 | 宿主事件循环暂停后接受超过 500 ms 的结果 — DYNAMIC | 冻结接收计时契约，修 deadline，加入 delayed-host 回归 |
| G0-04 | P1 | 普通线程上限未强制，CPU quota 仅声明 — 线程 DYNAMIC / CPU STATIC | 确定可执行 runtime profile，不将库环境变量称为 OS 配额 |
| G0-05 | P1 | 极窄圆相交未截断，误杀后方点 — DYNAMIC | 单独批准基线正确性修复，加入独立解析和镜像对照 |
| G0-06 | P1 | 交互终端自动选锁且接受出厂槽位，默认 Web 不同 — DYNAMIC + STATIC | 决定正式终端地位；统一或明确限制，不能静默改变策略决策权 |
| G0-07 | P1 | 揭晓前观众障碍物可见，与 Team 活跃文案冲突 — 投影 DYNAMIC / 匿名传输 STATIC | 明确人类角色与算法输入可见性；任一方向都不自动属于样式修复 |
| G0-08 | P2 | 部分筹备阶段按钮可用但执行被拒 — DYNAMIC | 共用可续跑策略或正确投影，加入中间态测试 |
| G0-09 | P2 | platform mismatch 可报 OK，runtime 信息不完整/缓存 — 纯函数 DYNAMIC + STATIC | 展示实际有效身份和观测时间，保留 warning/blocker 区分 |
| G0-10 | P2 | 旧 Emitter 注释、硬上限优先级及公开公平报告不符代码 — STATIC | 明确基线、恢复有证据的公开说明，不重写历史产物 |
| G0-11 | P2 | 清理/存储异常及 slot/sealed/preflight 身份弱于泛化承诺 — STATIC | 生命周期/事务及状态真实性收口，列清未动态测试项 |

额外设计缺口：结果文件读取前字节上限、临时写总量配额、完整 import allowlist、回放认证、进行中比赛恢复均未实现；内存是 best-effort 采样。这些不全是新引入 bug，单纯缺少未来 V1.5 能力也不等于 V1.4 违规。

替换后复验失败的槽位回滚、rehash 后复制竞争、全局诊断字符串被静态列入后续定向范围。本轮没有动态触发，不得作为已验证攻击或扩展成全面 exploit campaign。

## 7. V1.5.0 范围建议 — 未冻结、未授权

### 前置：明确处置基线

声称关键漂移为零之前，应处置 G0-01～G0-07 并澄清 G0-10。这不等于自动重开 V1.4 纯文档发布。建议单独批准 V1.5 基线修复范围，保留旧版本 tree 和历史证据。计时、几何修复应独立归因和验证，不藏在 UX commit 中。

### 前置评审后 V1.5.0 可纳入

1. 在既有 `startServer` 外封装薄 TournamentLauncher，提供 `npm run tournament` 与清楚区分的开发入口。
2. Doctor 结构化 PASS/WARN/BLOCK，记录真实 Node/Python/backend/目录/前端/端口观测与可行动错误。
3. 服务端共用 eligibility/action-policy 投影，执行时复核；未知不得画绿。
4. Judge 四态 SETUP/READY/LIVE/RESULT、Team 四步 Upload/Verify/Lock/Ready 只做**展示聚合**，不改引擎阶段或战斗语义。
5. 分开 slot、本场 sealed、preflight、runtime/security、持久化状态；组件化 readiness/卡片/控制/技术细节。
6. 双语错误 key+params、按角色过滤技术详情；验收键盘/焦点/禁用原因和四视口。
7. 启动资源归属/清理、实际端口、浏览器失败恢复；build reuse 测量后可选。

### 不纳入
