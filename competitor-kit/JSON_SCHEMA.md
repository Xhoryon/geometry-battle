# JSON Schema Reference

This document describes the field structure of three formal JSON files. The fields are produced by the **live engine**
and continuously verified by `tests/competitor-kit.ts` (the key set of real examples must match the machine-readable block in this file).

Corresponding real examples:

- [`examples/public_state.json`](examples/public_state.json)
- [`examples/reveal_state.json`](examples/reveal_state.json)
- [`examples/result.json`](examples/result.json)

> These three files are **byte-for-byte** engine artifacts (single-line compact JSON, no trailing newline),
> regenerated by `npx ts-node src/operator/generate-kit-examples.ts`,
> and checked against drift by `tests/competitor-kit.ts`.
> Examples are taken from **round 1**, so all `points[].alive` are `true`;
> from round 2 onward, killed points remain in `points` with `"alive": false` (spec §5).

## 0. Machine-readable field table

Tests read this block and check it against real examples.

```json
{
  "schema_version": "1.1",
  "public_state": {
    "required": ["schema_version", "match_id", "round", "map", "emitters", "points"],
    "map_fields": ["xmin", "xmax", "ymin", "ymax"],
    "emitter_fields": ["A", "B"],
    "emitter_point_fields": ["x", "y"],
    "point_fields": ["id", "team", "x", "y", "alive"],
    "forbidden": ["seed", "map_seed", "obstacles", "shooters", "map_hash"]
  },
  "reveal_state": {
    "required": ["schema_version", "match_id", "round", "public_state_sha256", "obstacles"],
    "obstacle_rectangle_fields": ["id", "type", "xmin", "xmax", "ymin", "ymax"],
    "obstacle_circle_fields": ["id", "type", "cx", "cy", "radius"]
  },
  "result": {
    "required": ["schema_version", "dsl"],
    "only_keys": ["schema_version", "dsl"]
  }
}
```

## 1. `public_state.json`

**Location**: provided by `--public` parameter (do not hardcode paths).
**Timing**: generated during PUBLIC phase; hidden information (obstacles, map seed) is not yet written.
**Both teams receive byte-identical content.**

> **Revision 3 change**: `emitters` has entered public. Fixed Emitter is a **public** structure that remains unchanged
> throughout the match, not hidden information — therefore visible during PUBLIC phase, no need to wait for reveal.

| Field | Type | Description |
|---|---|---|
| `schema_version` | string | Always `"1.1"` |
| `match_id` | string | Match identifier |
| `round` | integer | Round number (formal rounds start at 1; Preflight uses 0) |
| `map` | object | Field boundaries |
| `map.xmin` / `map.xmax` | number | `-20` / `20` |
| `map.ymin` / `map.ymax` | number | `-12` / `12` |
| `emitters` | object | Both sides' **fixed Emitter** coordinates (unchanged throughout match) |
| `emitters.A` / `emitters.B` | object | `{ "x": number, "y": number }` — your emission anchor point for this round |
| `points` | array | **All combat points**, **including dead points** (**excluding Emitters**) |
| `points[].id` | string | e.g. `"A1"` / `"B3"` (stable throughout match, but not necessarily consecutive; `A1` may be absent, see §4) |
| `points[].team` | string | `"A"` or `"B"` |
| `points[].x` / `points[].y` | number | Coordinates |
| `points[].alive` | boolean | `false` means this point has been killed |

**What is NOT in public** (do not look for these):

```text
Obstacles, map seed (seed / map_seed), map hash
```

> Emitters **will not** appear in `points`. They are emission anchor points, not combat points:
> not counted in survival count, cannot be killed, and cannot be targeted for strikes (Revision 3 §3/§7).

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "public_state.json",
  "type": "object",
  "required": ["schema_version", "match_id", "round", "map", "emitters", "points"],
  "additionalProperties": false,
  "properties": {
    "schema_version": { "const": "1.1" },
    "match_id": { "type": "string" },
    "round": { "type": "integer", "minimum": 0 },
    "emitters": {
      "type": "object",
      "required": ["A", "B"],
      "additionalProperties": false,
      "properties": {
        "A": { "type": "object", "required": ["x", "y"], "additionalProperties": false,
               "properties": { "x": { "type": "number" }, "y": { "type": "number" } } },
        "B": { "type": "object", "required": ["x", "y"], "additionalProperties": false,
               "properties": { "x": { "type": "number" }, "y": { "type": "number" } } }
      }
    },
    "map": {
      "type": "object",
      "required": ["xmin", "xmax", "ymin", "ymax"],
      "additionalProperties": false,
      "properties": {
        "xmin": { "type": "number" }, "xmax": { "type": "number" },
        "ymin": { "type": "number" }, "ymax": { "type": "number" }
      }
    },
    "points": {
      "type": "array",
      "items": {
        "type": "object",
        "required": ["id", "team", "x", "y", "alive"],
        "additionalProperties": false,
        "properties": {
          "id": { "type": "string" },
          "team": { "enum": ["A", "B"] },
          "x": { "type": "number" }, "y": { "type": "number" },
          "alive": { "type": "boolean" }
        }
      }
    }
  }
}
```

## 2. `reveal_state.json`

**Location**: provided by `--reveal` parameter.
**Timing**: generated during REVEAL phase.
**Semantics**: this is an **incremental** file — it does not repeat `points` / `map` / `alive` / `emitters`, only supplements hidden information.

> **Revision 3 change**: `shooters` has been removed from reveal. The per-round Shooter Selection was the old rule,
> replaced by fixed Emitter; emission anchor points are now provided in `public_state.emitters`.
> REVEAL now contains **only obstacles** as hidden information.

| Field | Type | Description |
|---|---|---|
| `schema_version` | string | Always `"1.1"` |
| `match_id` | string | Same as public |
| `round` | integer | Same as public |
| `public_state_sha256` | string | SHA-256 of public file **bytes** (for binding) |
| `obstacles` | array | Obstacles for this round |

`obstacles[]` has two shapes (distinguished by `type`):

| type | Fields |
|---|---|
| `"rectangle"` | `id`, `type`, `xmin`, `xmax`, `ymin`, `ymax` |
| `"circle"` | `id`, `type`, `cx`, `cy`, `radius` |

> Emission anchor points are not in reveal — they are **directly provided as coordinates** in `public_state.emitters`,
> and remain the same value throughout the match. You do not need to (and cannot) reverse-lookup them from any point table.

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "reveal_state.json",
  "type": "object",
  "required": ["schema_version", "match_id", "round", "public_state_sha256", "obstacles"],
  "additionalProperties": false,
  "properties": {
    "schema_version": { "const": "1.1" },
    "match_id": { "type": "string" },
    "round": { "type": "integer", "minimum": 0 },
    "public_state_sha256": { "type": "string", "pattern": "^[0-9a-f]{64}$" },
    "obstacles": {
      "type": "array",
      "items": {
        "oneOf": [
          {
            "type": "object",
            "required": ["id", "type", "xmin", "xmax", "ymin", "ymax"],
            "additionalProperties": false,
            "properties": {
              "id": { "type": "string" }, "type": { "const": "rectangle" },
              "xmin": { "type": "number" }, "xmax": { "type": "number" },
              "ymin": { "type": "number" }, "ymax": { "type": "number" }
            }
          },
          {
            "type": "object",
            "required": ["id", "type", "cx", "cy", "radius"],
            "additionalProperties": false,
            "properties": {
              "id": { "type": "string" }, "type": { "const": "circle" },
              "cx": { "type": "number" }, "cy": { "type": "number" },
              "radius": { "type": "number" }
            }
          }
        ]
      }
    }
  }
}
```

### Binding validation (recommended)

```python
import hashlib, json
public_bytes = open(args.public, "rb").read()
reveal = json.load(open(args.reveal))
assert hashlib.sha256(public_bytes).hexdigest() == reveal["public_state_sha256"]
```

When binding fails, the platform will reject this round's input (Bootstrap will exit during startup phase).
Regular algorithms do **not need** to validate this themselves, but validating once is cheap self-protection.

## 3. `result.json`

**Location**: provided by `--output` parameter.
**Requirement**: top level must have **exactly** two keys; one extra key and it is deemed illegal.

| Field | Type | Description |
|---|---|---|
| `schema_version` | string | MUST be exactly `"1.1"` |
| `dsl` | object or string | Function AST (see [DSL_SPECIFICATION.md](DSL_SPECIFICATION.md)) |

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "result.json",
  "type": "object",
  "required": ["schema_version", "dsl"],
  "additionalProperties": false,
  "properties": {
    "schema_version": { "const": "1.1" },
    "dsl": { "type": ["object", "string"] }
  }
}
```

For write method, see the "Result Submission" section in [ALGORITHM_REQUIREMENTS.md](ALGORITHM_REQUIREMENTS.md)
(temporary file + atomic replacement).

## 4. Things not to assume

- **Do not assume fixed point count**: each team has 6–10 points, varying.
- **Do not assume a specific ID must exist**: `A1` / `B1` are just initial IDs. IDs are **stable** throughout the match and do not disappear due to kills
  (dead points remain in place with `"alive": false`), but the two IDs locked as Emitters are **not in `points`** —
  for example, `A1` may never exist from start to finish, and IDs are not necessarily consecutive.
- **Do not assume Emitter coordinates are fixed**: it is a point selected from **each team's own points** before match start,
  varying per match — you MUST read `public_state.emitters`, do not hardcode `-18` / `18`.
  The point selected as Emitter is **not in `points`** (it is no longer a combat point).
- **Do not assume fixed obstacle count or type**: may be 0, may be multiple; current types are `rectangle` / `circle`.
- **Do not infer semantics from JSON field order**: parse by key name, not position.
- **Do not infer geometry from array order**: the order of `points` is **not** x ascending or distance from Emitter ascending
  (the engine only guarantees those in §4.1).
- **Do not rely on map seed**: it is not in public, you cannot get it.

### 4.1 Array-order guarantees

The engine **only** guarantees these about order (all else is not guaranteed):

- `points`: all Team A entries first, then all Team B entries; within each group, in map generation / placement order (`A1, A2, …`, `B1, B2, …`).
- `points`: **same order, same entry count** every round throughout the match — killed points stay in place with only `alive` set to `false`; entries **do not** disappear on a kill.
- `points`: the two points locked as Emitters are removed, and remaining IDs are **not renumbered** (so `A1` may be absent).
- `obstacles`: numbered `O1..On` in generation order, and the array is the same every round throughout the match.

**Do not assume array order represents x ascending, distance from Emitter ascending, or any other geometric ordering.**
