# Runtime Manifest

This file describes the runtime environment available **inside the official Sandbox** (i.e., where your `solver.py` actually runs).

This Manifest is generated by a real sandbox probe and continuously verified by the permanent regression test `tests/runtime-manifest.ts`:
**Modules that the Manifest claims are importable MUST be importable in the official sandbox; packages claimed unavailable MUST NOT be advertised as available in any public documentation.**

> Note: Your host machine may have additional libraries installed (e.g., `import numpy` may succeed on your development machine),
> but those libraries are **NOT** in the official sandbox. Rely only on what this Manifest lists.

## 3. Third-Party Packages: None

```text
Third-party packages: NONE
```

The official sandbox has **NO third-party Python packages**. The following packages are verified unavailable:

```text
numpy  scipy  sympy  torch  pandas  matplotlib  sklearn  numba
cvxpy  z3  networkx  jax  tensorflow  statsmodels
```

Therefore:

- Do NOT `import numpy` / `import scipy` (will fail with `ModuleNotFoundError`, Preflight will fail);
- Do NOT run `pip install` / `conda install` (sandbox denies process creation, and has no network);
- For mathematical computation, use standard library modules: `math`, `cmath`, `decimal`, `fractions`, `statistics`,
  `random`, `itertools`, `functools`, etc.

> Historical note: Early versions of public documentation listed `numpy 2.0.2` / `scipy 1.13.1` as frozen dependencies.
> Those were **host observation** results, not sandbox reality. This Manifest and permanent tests supersede them.

## 4. Importable but Functionally Restricted

These modules `import` successfully, but **will be blocked by the sandbox when used**:

| Module | Restriction Reason | Observed Result |
|---|---|---|
| `subprocess` | Sandbox `(deny process-fork)` | `PermissionError: [Errno 1] Operation not permitted` |
| `multiprocessing` | Same (requires fork) | `PermissionError: [Errno 1] Operation not permitted` |
| `socket` | Sandbox `(deny network*)` | `PermissionError: [Errno 1] Operation not permitted` |

Do not rely on them: for parallel computation, use single-process algorithms (thread limit is also 1).

The following capabilities are verified **available**:

| Capability | Observed Result |
|---|---|
| `ctypes` calling libc | OK |
| `mmap` anonymous mapping | OK |
| `signal.alarm` | OK |
| `/dev/urandom` reading | OK (per-process random source) |
| `tempfile.NamedTemporaryFile` | OK, created in current working directory |

## 6. Environment Variables

Host environment variables are **NOT inherited**: the platform explicitly constructs a minimal environment. The table below lists **all variables set by the platform**.
In practice, the sandbox also sees a small number of benign variables injected by macOS and the process launcher
(`CPATH`, `LIBRARY_PATH`, `MANPATH`, `PWD`, `SDKROOT`, `SHLVL`, `__CF_USER_TEXT_ENCODING`).
These contain no sensitive host information, but do not rely on them.

Variables explicitly set by the platform:

```text
PATH          /usr/bin:/bin:/usr/sbin:/sbin
HOME          <sandbox directory>
TMPDIR        <current working directory>  ← writable
LANG / LC_ALL C.UTF-8
PYTHONDONTWRITEBYTECODE 1
PYTHONUNBUFFERED        1
PYTHONHASHSEED          0
PYTHONNOUSERSITE        1
GB_TEAM                  A | B
OMP_NUM_THREADS and similar thread vars  1
```

For temporary files, use `tempfile` or the current working directory, see [ALGORITHM_REQUIREMENTS.md](ALGORITHM_REQUIREMENTS.md) §8 "Working Directory and Temporary Files".

## 7. Runtime Change Rules

The Runtime is not a variable in the competition, but a **frozen item**: both sides run in exactly the same Runtime.

If the Runtime changes in the future (adding or removing any module):

1. MUST synchronously update the machine-readable block in this Manifest;
2. MUST make `tests/runtime-manifest.ts` pass;
3. MUST NOT write a manifest in other public documentation that conflicts with this Manifest.

Modules not listed in `verified_importable` are considered **unavailable**.
